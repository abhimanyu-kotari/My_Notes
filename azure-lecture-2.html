Compute: Azure Virtual Machines (Complete Walkthrough)

What is this module about? The definitive masterclass on Azure Virtual Machines: 3 distinct deployment methods (Cloud Shell in-browser, local PC terminal via Azure CLI, and the full Azure Portal GUI), fixing SSH permissions on Windows and macOS, executing hardware and cloud metadata inspection commands, setting up Nginx web servers, troubleshooting NSG firewall blocks, formatting and persisting attached data disks, and mastering the Stopped vs. Deallocated billing trap.

01. The Anatomy of an Azure Virtual Machine

When you create an Azure VM, Azure provisions a coordinated set of interconnected cloud infrastructure resources:

🖥️ Azure Virtual Machine Architecture Blueprint vCPU • RAM • NIC • Disks
1. Compute Host

Allocates dedicated vCPUs and RAM on physical hypervisors.

Size: Standard_B1s (1 vCPU, 1 GB)
2. Network Interface (NIC)

Bridges VM to VNet and assigns IP addresses.

Private IP: 10.0.0.4 | Public IP: 20.x.x.x
3. Network Security Group (NSG)

Stateful virtual firewall protecting inbound/outbound ports.

Port 22 (SSH) | Port 80 (HTTP)
4. Storage Array

OS disk (persistent), Data disk (persistent), Temp disk (ephemeral wipe).

/dev/sda1 (OS) • /dev/sdb1 (/mnt)

02. VM Sizing & Series Families

Azure names VM sizes systematically (e.g., Standard_B1s, Standard_D4s_v5). The first letter designates the computational specialization:

Series Category Best Suited For Free Tier Eligible?
B-Series Burstable Compute Student labs, low-traffic websites, dev/test environments. Accrues CPU credits during idle time and bursts up to 100% when active. ✅ YES (B1s - 750 hrs/mo)
D-Series General Purpose Balanced CPU-to-memory ratio (4GB RAM per vCPU). Production web servers, medium SQL databases. No
F-Series Compute Optimized High clock speeds. Batch processing, video transcoding, math algorithms. No
E-Series Memory Optimized Large RAM-to-CPU ratio (8GB+ RAM per vCPU). In-memory caching (Redis), SAP HANA. No
N-Series GPU Accelerated Equipped with NVIDIA Tesla GPUs for Deep Learning training and LLM inference. No

03. Managed Disks & The Ephemeral Temporary Disk Trap

Every Azure VM connects to 3 distinct categories of storage:

1. OS Disk (Persistent)

Holds the OS boot files (Linux / or Windows C:). Never erased upon VM stop or reboot.

2. Data Disks (Persistent)

Dedicated managed disks attached to the VM for databases and application files. Persist independently.

3. Temporary Disk (EPHEMERAL)

Physical SSD on the host server (/mnt or D:). All data is permanently wiped on deallocate/maintenance!

🚨 The Temporary Disk Wipe Trap:

Azure automatically creates a file named /mnt/DATALOSS_WARNING_README.txt on every Linux VM. It warns: "Any data stored on this drive will NOT be recovered during events like VM migration or resize." Never put your code, databases, or documents in /mnt!

04. Method 1: Creating a VM via Azure Cloud Shell (In-Browser CLI)

The fastest way to deploy a VM without installing anything on your laptop is the in-browser **Azure Cloud Shell**.

💻 Method 1 • Cloud Shell (Bash)
Azure Cloud Shell (Bash)
# 1. Create a dedicated Resource Group in East US user@Azure:~$ az group create --name rg-azure-demo --location eastus # 2. Deploy Ubuntu 22.04 VM with auto-generated SSH keys user@Azure:~$ az vm create \ --resource-group rg-azure-demo \ --name vm-cloudshell-demo \ --image Ubuntu2204 \ --size Standard_B1s \ --admin-username azureuser \ --generate-ssh-keys \ --public-ip-sku Standard # 3. Check VM Status and inspect its assigned Public IP user@Azure:~$ az vm show -d -g rg-azure-demo -n vm-cloudshell-demo \ --query "{Name:name, PublicIP:publicIps, State:powerState}" -o table # 4. Open Port 80 for Web Traffic user@Azure:~$ az vm open-port \ --resource-group rg-azure-demo \ --name vm-cloudshell-demo \ --port 80 \ --priority 100

05. Method 2: Creating a VM from Our Local Computer (Terminal / PowerShell)

You can manage and provision Azure resources from your local laptop using the official Azure CLI.

🖥️ Method 2 • Local Computer Terminal

Step 1: Install Azure CLI Locally

  • Windows (PowerShell): winget install -e --id Microsoft.AzureCLI
  • macOS (Homebrew): brew install azure-cli
  • Linux (Ubuntu/Debian): curl -sL https://aka.ms/InstallAzureCLIDeb | sudo bash

Step 2: Authenticate and Create VM

Local Terminal (PowerShell / Bash)
# 1. Sign in to your Azure account via browser popup $ az login # 2. Generate custom SSH key pair on your computer $ ssh-keygen -t rsa -b 4096 -f ~/.ssh/azure_local_key # 3. Provision VM using your local public key $ az vm create \ --resource-group rg-azure-demo \ --name vm-from-local \ --image Ubuntu2204 \ --size Standard_B1s \ --admin-username azureuser \ --ssh-key-values ~/.ssh/azure_local_key.pub \ --public-ip-sku Standard

06. Method 3: Creating a VM via Azure Portal (GUI Step-by-Step)

🖱️ Method 3 • Azure Portal (portal.azure.com)
1. Basics Tab Configuration
  • Subscription: Select your Free Trial or active subscription.
  • Resource Group: Select rg-azure-demo (or click *Create new*).
  • Virtual Machine Name: vm-portal-demo
  • Region: East US • Availability zone: Zone 1
  • Image: Ubuntu Server 22.04 LTS - x64 Gen2
  • Size: Select Standard_B1s (1 vCPU, 1 GiB memory) — Eligible for free tier.
  • Authentication Type: Select SSH public key → Username: azureuser.
  • Inbound Port Rules: Select ports SSH (22) and HTTP (80).
2. Disks & Networking Tabs
  • OS Disk Type: Select Standard SSD (locally-redundant storage).
  • Delete with VM: Ensure the checkbox is Checked for both OS disk and NIC/Public IP.
3. Management Tab: The Auto-Shutdown Safeguard

Never leave a VM running overnight by accident!

  • Check Enable auto-shutdown.
  • Set shutdown time to 19:00:00 (7:00 PM local time).
  • Enter your notification email to receive confirmation when Azure powers it down.
4. Review + Create & Download Key

Click Review + create. When validation passes, click Create. In the popup, click Download private key and create resource to save vm-portal-demo.pem on your machine!

07. Connecting via SSH & Fixing Key Permissions

1. On macOS / Linux:

# Set strict read-only permissions on private key $ chmod 400 ~/.ssh/vm-portal-demo.pem # Connect via SSH $ ssh -i ~/.ssh/vm-portal-demo.pem azureuser@<VM_PUBLIC_IP>

2. On Windows (Fixing "UNPROTECTED PRIVATE KEY FILE" Error):

⚠️ Windows PowerShell Key Permissions: Windows file permissions often grant read rights to "Users" or "Everyone", which SSH rejects with Permissions for 'key.pem' are too open. Run these two commands in PowerShell to fix it immediately:
Windows PowerShell (Administrator / User)
# Step 1: Remove inherited permissions PS C:\> icacls.exe .\vm-portal-demo.pem /inheritance:r # Step 2: Grant read permission strictly to your current Windows username PS C:\> icacls.exe .\vm-portal-demo.pem /grant:r "$($env:USERNAME):(R)" # Step 3: Connect cleanly! PS C:\> ssh -i .\vm-portal-demo.pem azureuser@<VM_PUBLIC_IP>

08. Inside the VM: Comprehensive System Inspection Commands

Once you are connected to your virtual machine terminal, run these commands to inspect hardware, storage, and cloud metadata:

azureuser@vm-portal-demo:~
# 1. Kernel and architecture details azureuser@vm:~$ uname -a # 2. Detailed CPU core count, hypervisor brand, and architecture azureuser@vm:~$ lscpu # 3. Check RAM memory allocation in human-readable MB / GB azureuser@vm:~$ free -m -h # 4. Check mounted storage filesystems and free disk space azureuser@vm:~$ df -h # 5. List block devices (Notice sda = OS disk, sdb = temporary disk) azureuser@vm:~$ lsblk # 6. Read the actual Microsoft warning text on the ephemeral temp disk! azureuser@vm:~$ cat /mnt/DATALOSS_WARNING_README.txt # 7. Check internal private network IP (eth0) azureuser@vm:~$ ip a # 8. Query the Azure Instance Metadata Service (IMDS) from inside the VM! azureuser@vm:~$ curl -s -H Metadata:true --noproxy "*" \ "http://169.254.169.254/metadata/instance?api-version=2021-02-01" | python3 -m json.tool

09. Installing Nginx & Troubleshooting NSG Port 80 Firewall Blocks

Step 1: Install Nginx Web Server

azureuser@vm:~$ sudo apt update azureuser@vm:~$ sudo apt install nginx -y azureuser@vm:~$ sudo systemctl status nginx

Step 2: Test Locally

azureuser@vm:~$ curl -I http://localhost HTTP/1.1 200 OK Server: nginx/1.18.0 (Ubuntu)

Step 3: Test from External Browser & Troubleshoot NSG

Open your browser and navigate to http://<VM_PUBLIC_IP>. If the page loads the default welcome page, everything succeeded! If the browser hangs indefinitely, port 80 is blocked by your Network Security Group (NSG).

Cloud Shell / Local Terminal • Fix NSG Rule
# 1. List existing NSG rules $ az network nsg rule list -g rg-azure-demo --nsg-name vm-cloudshell-demoNSG -o table # 2. Add Inbound Allow Rule for Port 80 (HTTP) $ az network nsg rule create \ --resource-group rg-azure-demo \ --nsg-name vm-cloudshell-demoNSG \ --name Allow-HTTP-80 \ --priority 110 \ --direction Inbound \ --access Allow \ --protocol Tcp \ --destination-port-ranges 80

10. Attaching, Formatting & Persisting a Data Disk

Step 1: Attach New 10 GB Managed Disk via CLI
$ az vm disk attach \ --resource-group rg-azure-demo \ --vm-name vm-cloudshell-demo \ --name datadisk-01 \ --size-gb 10 \ --new \ --sku StandardSSD_LRS
Step 2: Format and Mount Inside the VM
# 1. Check disk block name (shows new /dev/sdc disk) azureuser@vm:~$ lsblk # 2. Format with ext4 filesystem azureuser@vm:~$ sudo mkfs.ext4 /dev/sdc # 3. Mount to /datadrive azureuser@vm:~$ sudo mkdir -p /datadrive azureuser@vm:~$ sudo mount /dev/sdc /datadrive # 4. Persist in /etc/fstab using UUID so it auto-mounts on reboot azureuser@vm:~$ echo "UUID=$(sudo blkid -s UUID -o value /dev/sdc) /datadrive ext4 defaults,nofail 1 2" | sudo tee -a /etc/fstab

11. The Cost Trap: "Stopped" vs. "Stopped (Deallocated)"

State How It Happened Compute Billed (vCPU/RAM)? Storage Disks Billed?
Stopped Ran sudo poweroff inside Linux OS terminal. ❌ YES (Still billed!) Yes
Stopped (Deallocated) Clicked Stop in Portal or ran az vm deallocate. ✅ $0.00 / hour (Compute freed!) Only storage disks
# Proper way to stop compute billing via CLI: $ az vm deallocate --resource-group rg-azure-demo --name vm-cloudshell-demo # Start the VM again: $ az vm start --resource-group rg-azure-demo --name vm-cloudshell-demo

12. Complete Lab Teardown Protocol ($0 Bill Guarantee)

When you finish your practice session, delete the entire Resource Group to immediately destroy the VM, all disks, NICs, public IPs, and NSGs in a single command:

$ az group delete --name rg-azure-demo --yes --no-wait
