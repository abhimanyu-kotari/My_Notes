01. Laptop vs. Server & Lab Overview

Personal Computer vs. Production Server:

What is the fundamental difference between your personal laptop and a production cloud server?

💻 Personal Computer (Laptop)

Used for individual daily tasks (browsing, writing code, gaming). Shut down when you sleep, connected via dynamic private IP behind your home Wi-Fi router.

🌐 Production Server

Its entire job is to actively serve content (web pages, databases, APIs) 24/7/365 without interruption. Hosted in an enterprise datacenter with redundant power and a public static IP.

Why Do We Call It a "Virtual" Machine?

Because there is no physical tower or server box sitting in your room. Microsoft allocates dedicated vCPU cores, RAM memory, and disk storage on its physical enterprise hypervisors, and you connect to and manage it entirely over the internet.

The Two Production Labs We Are Building:

  • Lab 1 (Linux Ubuntu): Deploying an Ubuntu 22.04 VM, bootstrapping the Apache2 web server using automated cloud-init custom data, connecting via in-portal CLI terminal, and opening Port 80 in NSG.
  • Lab 2 (Windows Server): Provisioning a Windows Server 2022 VM, connecting via graphical Remote Desktop Protocol (RDP Port 3389), and installing Microsoft's Internet Information Services (IIS) web server.

04. Linux VM: Cloud-Init Apache Script

Rather than manually SSHing into the VM after boot to type install commands, the instructor automates the entire web server provisioning using Custom data (cloud-init):

  1. Click Next : Disks (leave Standard SSD defaults).
  2. Click Next : Networking (Azure prepares virtual network, subnet, and public IP).
  3. Click Next : Management → Next : Monitoring → Next : Advanced.
  4. Scroll down to the Custom data box and paste the bash script:
cloud-init-bootstrap.sh (Custom Data) 
#!/bin/bash
# 1. Update Ubuntu local package repository index
apt-get update -y

# 2. Install the Apache2 HTTP web server
apt-get install -y apache2

# 3. Start Apache immediately
systemctl start apache2

# 4. Enable Apache to auto-start on system boots
systemctl enable apache2

# 5. Overwrite the default landing page with a custom heading
echo "<h1>Welcome to Apache Web Server on Azure</h1>" > /var/www/html/index.html
How Cloud-Init Works: During the initial Linux kernel boot, cloud-init runs with root privileges and executes this script before user login. Your web server is serving traffic the instant provisioning finishes.

09. Port 80 Browser Timeout Trap & NSG Fix

The Real-World Problem:

Copy the Public IP address of your VM (e.g., 20.198.x.x), paste it into your computer's browser tab, and press Enter. The tab spins indefinitely and eventually crashes with ERR_CONNECTION_TIMED_OUT!

Why did it fail? Apache is running perfectly inside the VM. The block happens at the Network Security Group (NSG) perimeter firewall. By default, Azure NSGs enforce a Default Deny policy for all inbound internet traffic except the ports you explicitly allow. Since we only allowed Port 22 (SSH), Port 80 (HTTP) traffic is dropped.

The Fix (Adding Inbound Rule):

  1. In the VM left menu, click Networking (or Network settings).
  2. Notice the Inbound port rules table has SSH (Port 22) allowed, followed by DenyAllInBound.
  3. Click + Add inbound port rule on the top right.
  4. Set Service to HTTP (Port 80, Protocol TCP), Action to Allow, Priority to 310, and Name to Allow-HTTP-Port-80.
  5. Click Add. Wait 5 seconds, then refresh your browser tab on http://<VM_PUBLIC_IP>.
  6. Success! The heading "Welcome to Apache Web Server on Azure" renders instantly.

11. Windows VM: Connecting via RDP (Port 3389)

Once my-windows-server reaches the Running state:

  1. Click on my-windows-server → in the top action bar, click Connect → select RDP.
  2. Under Native RDP, confirm the Public IP and Port (3389) → click Download RDP file.
  3. Save my-windows-server.rdp to your desktop.
  4. Launch Remote Desktop:
    • Windows PC: Double-click the file to launch mstsc.exe.
    • macOS: Open Microsoft Remote Desktop from the Mac App Store and drop the .rdp file into it.
  5. Click Connect when prompted by the unknown publisher warning.
  6. Enter your username (azureuser) and password. Accept the certificate prompt by clicking Yes.
  7. Boom! The full graphical Windows Server 2022 desktop launches in a window on your screen.

12. Windows VM: Installing IIS Web Server

Inside the Windows remote desktop, the instructor installs Microsoft's native web server: Internet Information Services (IIS).

Installing via PowerShell (Automated 1-Liner):

  1. Inside the remote desktop session, click the Start menu.
  2. Right-click Windows PowerShell → select Run as administrator.
  3. Run the official feature installation command:
PowerShell (Run as Administrator inside Windows VM) 
Install-WindowsFeature -name Web-Server -IncludeManagementTools

Verifying & Exposing IIS:

  1. Open Microsoft Edge inside the Windows remote desktop and visit http://localhost.
  2. Local Test: The official blue Internet Information Services (IIS) welcome page appears!
  3. Internet Test: Go back to Azure Portal → my-windows-server-nsg → Add an Inbound Rule allowing HTTP (Port 80).
  4. Now anyone in the world can load your Windows Server IIS website via its Public IP!

14. Local Terminal SSH Access

To connect to your Linux VM directly from your local terminal using the downloaded my-web-server_key.pem:

macOS / Linux Terminal:

# 1. Lock down permissions so SSH doesn't reject an open key file
chmod 400 ~/Downloads/my-web-server_key.pem

# 2. Connect via SSH
ssh -i ~/Downloads/my-web-server_key.pem azureuser@<VM_PUBLIC_IP>

Windows PowerShell:

# 1. Reset permissions so only your Windows account can read the key
icacls .\my-web-server_key.pem /inheritance:r
icacls .\my-web-server_key.pem /grant:r "$($env:USERNAME):(R)"

# 2. Connect via OpenSSH
ssh -i .\my-web-server_key.pem azureuser@<VM_PUBLIC_IP>

15. The Cost Trap: Stopped vs. Deallocated

The Biggest Azure Billing Pitfall: If you shut down a virtual machine from inside the operating system (e.g., Start → Shut Down in Windows or sudo poweroff in Ubuntu), Azure status displays Stopped. Microsoft CONTINUES TO CHARGE YOU for the compute cores because the physical host server remains reserved!
Portal Status Physical Hardware Reserved? Compute Billing Status
Running Yes (Dedicated host hypervisor slot) Billing active per second
Stopped (Guest Shutdown) Yes (Physical slot kept warm for you) BILL STILL CHARGES!
Stopped (deallocated) No (Hardware released back to Azure) $0 Compute Charges

The Fix: Always click the Stop button in the Azure Portal toolbar until the status explicitly reads Stopped (deallocated).

16. Clean Lab Teardown Protocol ($0 Bill)

Because all resources for both VMs reside inside azure-vm-rg, clean teardown requires only 1 operation:

  1. In the Azure search bar, type Resource groups and click azure-vm-rg.
  2. Click Delete resource group in the top menu.
  3. Type azure-vm-rg into the confirmation field and click Delete.
  4. Azure deletes both VMs, disks, public IPs, NICs, and VNets together, guaranteeing a $0 recurring bill!
