Compute (Azure Virtual Machines)

What is this module about? Deep dive into Azure Virtual Machines (IaaS compute): understanding VM sizing series (B-series burstable vs D/E/F/N series), managed OS and data disks, the critical data-loss trap of the ephemeral temporary disk, Network Security Group (NSG) priority rules, connecting via SSH key pairs and RDP, and avoiding surprise bills with Stopped vs. Stopped (Deallocated).
Why is this critical for engineers? Virtual machines are the compute backbone of the cloud. Every Kubernetes node, backend microservice host, and deep learning training cluster runs on top of these fundamental building blocks.

02. VM Sizing & Series Families

Azure names VM sizes systematically (e.g., Standard_D4s_v5). The first letter determines the hardware specialization:

Series Letter Category Best Suited For Cost Tier
B-Series Burstable Compute Development, student labs, low-traffic web servers. Accumulates CPU credits during idle times and bursts up to 100% CPU when busy. Lowest ($ / hr)
D-Series General Purpose Balanced CPU-to-memory ratio. Ideal for production web servers, small-to-medium databases, and application backends. Moderate
F-Series Compute Optimized High CPU clock speed per GB of RAM. Ideal for video transcoding, batch processing, gaming servers, and scientific math modeling. Medium - High
E-Series Memory Optimized Massive RAM-to-CPU ratio. Ideal for in-memory databases (SAP HANA, Redis cache), Elasticsearch, and big data data analytics. High
N-Series GPU Enabled Packed with NVIDIA Tesla / Ampere GPUs. Used for Deep Learning model training, AI inference, and 3D rendering. Enterprise High

03. Managed Disks & The Ephemeral Temporary Disk Warning

Every Azure VM connects to three distinct types of disks:

  1. OS Disk: Contains the operating system boot files (Windows C: drive or Linux / root). Persists even if the VM is rebooted or stopped.
  2. Data Disks: Additional persistent managed disks attached to the VM for storing database files, repositories, or application data.
  3. Temporary Disk: A physical SSD located directly on the physical host machine running your VM (labeled D: drive on Windows or /dev/sdb1 mounted at /mnt on Linux).
🚨 CRITICAL DATA-LOSS WARNING: The Temporary Disk is Ephemeral!

The temporary disk provides ultra-fast temporary storage for page files, swap files, and temporary caches. However, whenever your VM is stopped, deallocated, or migrated to a different physical server rack during Azure maintenance, EVERY BYTE OF DATA ON THE TEMPORARY DISK IS PERMANENTLY ERASED AND CANNOT BE RECOVERED. Never save databases, user uploads, or project files on the temporary drive!

Azure Managed Disk Performance Tiers:

  • Standard HDD: Magnetic spinning disk, cheapest cost. Best for dev/test environments and non-critical backups.
  • Standard SSD: Solid-state drive for light production workloads and consistent entry-level performance.
  • Premium SSD (v1 & v2): High-performance SSDs delivering up to 20,000 IOPS. Required for enterprise databases and mission-critical web applications.
  • Ultra Disk: Top-tier storage delivering up to 160,000 IOPS with sub-millisecond latency. Tuned for extreme transactional workloads.

04. Networking: VNet, Subnets & Network Security Groups (NSGs)

A Virtual Machine cannot communicate without network plumbing:

  • Virtual Network (VNet): Your private, isolated virtual network slice in the cloud (e.g., CIDR block 10.0.0.0/16).
  • Subnet: A segmented subdivision of your VNet (e.g., 10.0.1.0/24 for Web Subnet; 10.0.2.0/24 for Database Subnet).
  • Network Interface Card (NIC): The virtual network card linking the VM to the Subnet.

Network Security Group (NSG) Rules & Priorities

An NSG acts as a stateful virtual firewall controlling inbound and outbound traffic.

RULE PRIORITY NUMBER (100 to 4096) Lower numbers are evaluated FIRST! Once a match is found, evaluation stops. Priority | Name | Port | Protocol | Source | Action ----------+--------------------+------+----------+--------+--------- 100 | Allow-SSH | 22 | TCP | Any | ALLOW 110 | Allow-HTTP | 80 | TCP | Any | ALLOW 120 | Allow-HTTPS | 443 | TCP | Any | ALLOW 65000 | AllowVNetInBound | Any | Any | VNet | ALLOW 65500 | DenyAllInBound | Any | Any | Any | DENY <-- Default!
💡 Rule Priority Best Practice: Always leave gaps between rule priority numbers (e.g., 100, 110, 120). Never use consecutive numbers (100, 101, 102). This allows you to easily insert urgent emergency rules (like priority 105) between existing rules without having to renumber everything!

05. Connecting to Your VM: SSH Key Pairs vs. RDP

1. Connecting to Linux VMs via SSH Key Pair (Recommended):

Passwords are vulnerable to brute-force attacks. The modern standard is asymmetric cryptography using SSH keys (Private Key + Public Key):

ssh -i ~/.ssh/azure_key.pem azureuser@20.52.14.9

2. Connecting to Windows VMs via Remote Desktop Protocol (RDP):

For Windows Server VMs, download the .rdp file from the Azure portal, open the Remote Desktop Connection client on your computer, enter the administrator username and password, and interact with the full graphical Windows desktop.

06. Hands-On Walkthrough: Hosting an Nginx Web Server on Ubuntu VM

Follow these exact terminal steps after connecting via SSH:

# Step 1: Update package lists sudo apt update && sudo apt upgrade -y # Step 2: Install Nginx web server sudo apt install nginx -y # Step 3: Verify Nginx service is running sudo systemctl status nginx # Step 4: Create a custom homepage echo "<h1>Welcome to Microsoft Azure Zero to Hero!</h1><p>Hosted on Azure Virtual Machine</p>" | sudo tee /var/www/html/index.html
⚠️ Forgot Port 80 in NSG? If you paste the VM's Public IP address into your browser and the page keeps spinning indefinitely, your NSG firewall has not opened Port 80! Open the Azure Portal → Virtual Machine → Networking → Add inbound port rule → Destination port: 80 → Protocol: TCP → Action: Allow → Click Add. The site will load instantly!

07. The Cost Trap: "Stopped" vs. "Stopped (Deallocated)"

This is the most common reason students receive unexpected bills on Azure:

VM State How It Happened Compute Charges? Disk & IP Charges?
Stopped You typed sudo shutdown -h now inside the Linux OS terminal. YES! You are still billed for CPU & RAM! Yes
Stopped (Deallocated) You clicked Stop in the Azure Portal or ran az vm deallocate. NO! Compute charges drop to $0! Only for attached storage disks

08. Essential Azure CLI Commands for VMs

# Create an Ubuntu Linux VM with automatic SSH keys az vm create \ --resource-group my-rg \ --name my-ubuntu-vm \ --image Ubuntu2204 \ --admin-username azureuser \ --generate-ssh-keys \ --public-ip-sku Standard # Open Port 80 for HTTP traffic az vm open-port \ --resource-group my-rg \ --name my-ubuntu-vm \ --port 80 # Properly STOP and DEALLOCATE the VM (Stops compute billing!) az vm deallocate \ --resource-group my-rg \ --name my-ubuntu-vm # Start the VM again az vm start \ --resource-group my-rg \ --name my-ubuntu-vm # Delete the entire VM and associated disks cleanly az vm delete \ --resource-group my-rg \ --name my-ubuntu-vm \ --yes
