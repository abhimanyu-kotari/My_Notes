01. The Core Mental Model & What We Are Building

Personal Computer vs. Production Server:

What is the fundamental difference between your personal laptop and a production cloud server?

💻 Personal Computer (Laptop)

Used for daily personal tasks (browsing, writing code, gaming). It is shut down when you sleep, connects through domestic home Wi-Fi with a dynamic IP, and is not exposed to the public internet.

🌐 Production Server

Its entire job is to actively serve content (e.g. serving business web pages or APIs) 24 hours a day, 365 days a year without ever shutting down, running in an enterprise datacenter with redundant power and static public IPs.

Why Do We Call It a "Virtual" Machine?

Because there is no physical desktop tower in your room. The actual hardware sits inside Microsoft's enterprise datacenters. You simply choose your desired hardware specifications (vCPU cores, RAM memory, OS version, storage size) and manage it entirely over the internet.

The Real-Life Problem We Are Solving:

You have built a website for your business. The code is ready. Now you need a server to host it on the internet.

  • Old Way: Buy an expensive physical server, place it in your office, pay for 24/7 power, cooling, and commercial internet lines.
  • Azure Way: Rent an Ubuntu Virtual Machine in Azure, automatically install and configure the Apache2 web server via a startup script, connect to it via web terminal, and expose it safely to the global internet on Port 80.

02. Opening the Azure Portal & Checking Resources

The lecturer starts by navigating to the Azure web console:

  1. Open your browser and navigate to portal.azure.com.
  2. Sign in using your Microsoft Azure account.
  3. In the left-hand navigation menu, click on All resources:
    Notice that the resource list is initially completely empty. We have not created anything yet.
  4. In the top global search bar, type Virtual machines and select the service.
  5. On the Virtual Machines dashboard, click + Create → select Azure virtual machine.

03. Configuring the Virtual Machine (The Basics Tab)

⚙️ Azure Portal • Basics Configuration
1. Project Details
  • Subscription: Select your active subscription (e.g., Azure subscription 1 or Free Trial).
  • Resource Group: Every Azure resource must live inside a Resource Group. Click Create new → name: azure-vm-rg.
2. Instance Details
  • Virtual Machine Name: my-web-server
  • Region: Select the region closest to your target audience, e.g. (Asia Pacific) Central India (Pune).
  • Availability Options: Select Availability Zone → Zone 1 (Guarantees 99.99% high availability SLA via isolated datacenter buildings).
  • Security Type: Standard.
  • Image: Ubuntu Server 22.04 LTS - x64 Gen2 (LTS = 5 years free security patches).
  • Size: Select Standard_B1s (1 vCPU, 1 GiB RAM) — Free Tier Eligible (750 free hours/month).
3. Administrator Account (Authentication)
  • Authentication Type: Select SSH public key.
    (Passwords can be brute-forced by malicious bots; 2048-bit RSA keys cannot be cracked).
  • Username: azureuser (or your custom admin name).
  • SSH Public Key Source: Select Generate new key pair.
  • Key Pair Name: my-web-server_key.
4. Inbound Port Rules

Public inbound ports: Select Allow selected ports → check only SSH (22).

💡 Notice: In the lecture, we deliberately leave Port 80 (HTTP) closed for now so we can experience and troubleshoot the real-world firewall trap!

04. The Advanced Tab & Automated Cloud-Init Script

Instead of manually installing software after logging into the server, the lecturer configures the VM to install Apache automatically the instant it finishes booting!

Advanced Tab > Custom data and cloud-init

Scroll down to Custom data and paste the exact automated bash script:

Bash Bootstrap Script
#!/bin/bash apt-get update -y apt-get install -y apache2 systemctl start apache2 systemctl enable apache2 echo "<h1>Welcome to Apache Web Server on Azure</h1>" > /var/www/html/index.html
  • apt-get update -y: Refreshes the package manager index.
  • apt-get install -y apache2: Installs the Apache HTTP web server software.
  • systemctl start apache2: Launches the web server background daemon.
  • systemctl enable apache2: Ensures Apache restarts automatically on server reboot.
  • echo ... > /var/www/html/index.html: Writes our custom HTML landing page.

05. Review, Create & Downloading the Private Key

  1. Click the blue Review + create button at the bottom of the portal.
  2. Azure runs automated validation checks. Once it displays Validation passed, click Create.
  3. A modal popup appears: "Generate new key pair".
  4. Click the blue button: Download private key and create resource.
  5. Your web browser downloads the private key file: my-web-server_key.pem.
    ⚠️ Keep this file safe! If you lose this .pem file, you cannot download it again from Azure.
  6. Azure begins provisioning the virtual machine in the background.

06. What Did Azure Create in the Background?

While the deployment finishes, the lecturer navigates to All resources and opens Resource Group `azure-vm-rg`. Notice that Azure deployed 7 interconnected cloud components together:

Resource Name Azure Resource Type Operational Purpose
my-web-server Virtual Machine The compute processor and RAM running our Ubuntu OS.
my-web-server-nsg Network Security Group The virtual stateful firewall filtering port traffic.
my-web-server-ip Public IP Address The internet-facing IP address to access the server globally.
my-web-server-nic Network Interface (NIC) Connects the VM to the private virtual network.
azure-vm-rg-vnet Virtual Network (VNet) The isolated private software-defined network.
my-web-server_OsDisk_1 Managed Disk (SSD) The 30 GB persistent drive holding the Ubuntu filesystem.

07. Connecting to the VM via Azure Portal (SSH via Azure CLI)

Once deployment finishes, click Go to resource. The lecturer demonstrates connecting directly inside the Azure Portal without installing any local software:

  1. In the VM toolbar at the top, click Connect.
  2. Select More ways to connect → click SSH using Azure CLI.
  3. Click the blue button: Configure + Check Access.
    Azure automatically performs 4 health checks: verifies VM is running, port 22 is open, network interface is connected, and Cloud Shell proxy is authenticated.
  4. When all 4 checkmarks turn green, click the Connect button below them.
  5. A terminal drawer slides up at the bottom of the portal.
  6. When prompted: Are you sure you want to continue connecting (yes/no)? → Type yes and press Enter.
  7. Your live command prompt appears:
    azureuser@my-web-server:~$

08. Terminal Verification Commands (Run Inside the VM)

Now that you have a live terminal inside your cloud server, run the exact verification commands demonstrated in the video:

azureuser@my-web-server:~
# 1. Clear the terminal screen azureuser@my-web-server:~$ clear # 2. Check Apache service status (Must say: active (running)!) azureuser@my-web-server:~$ systemctl status apache2 ● apache2.service - The Apache HTTP Server Loaded: loaded (/lib/systemd/system/apache2.service; enabled; vendor preset: enabled) Active: active (running) since Tue 2026-11-17 14:30:12 UTC; 2min ago # 3. Inspect the custom HTML file created by our bootstrap script azureuser@my-web-server:~$ cat /var/www/html/index.html <h1>Welcome to Apache Web Server on Azure</h1> # 4. Test web server response locally inside the VM azureuser@my-web-server:~$ curl http://localhost <h1>Welcome to Apache Web Server on Azure</h1>

Apache responds with our custom HTML! This proves that the web server is actively running inside the VM.

09. The Port 80 Browser Timeout Trap & NSG Fix

The Real-World Problem:

1. Copy the Public IP address from your Azure Portal VM overview (e.g., 20.198.64.120).
2. Paste http://20.198.64.120 into a new browser tab and press Enter.
3. The browser tab continuously spins and eventually fails with:

⚠️ ERR_CONNECTION_TIMED_OUT: Even though Apache is running inside the VM and responding to curl http://localhost, external internet users cannot reach it! Why? Because in Step 3, we only opened Port 22 (SSH). Azure's default Network Security Group (NSG) firewall rule DenyAllInbound blocks Port 80 completely!

The Fix: Adding the Port 80 Inbound Rule

  1. In the Azure Portal, open your VM (my-web-server).
  2. In the left navigation menu under Networking, click Network settings (or Networking).
  3. Select the Inbound port rules tab.
  4. On the far right, click the Add inbound port rule button.
  5. In the configuration drawer, set:
    • Source: Any
    • Service: Select HTTP (automatically sets Port 80, Protocol TCP)
    • Action: Allow
    • Priority: 300 (must be lower number than 65500)
    • Name: Port_80 (or Allow-HTTP-80)
  6. Click Add. Wait 10 to 15 seconds for Azure to deploy the rule.
  7. Switch back to your browser tab with http://<Public-IP> and hit Refresh!
  8. "Welcome to Apache Web Server on Azure" loads immediately on your screen! 🎉

10. Connecting from Your Local Computer Terminal (Native SSH)

You can also connect to the VM directly from your laptop's terminal using the downloaded .pem key:

1. On macOS / Linux / WSL:

# Set strict read-only permissions on private key $ chmod 400 ~/Downloads/my-web-server_key.pem # Connect via SSH using the VM's Public IP $ ssh -i ~/Downloads/my-web-server_key.pem azureuser@<VM_PUBLIC_IP>

2. On Windows PowerShell (Fixing "Permissions are too open" error):

Windows PowerShell
# Remove inherited permissions PS C:\> icacls.exe .\my-web-server_key.pem /inheritance:r # Grant read permission strictly to your Windows username PS C:\> icacls.exe .\my-web-server_key.pem /grant:r "$($env:USERNAME):(R)" # Connect cleanly PS C:\> ssh -i .\my-web-server_key.pem azureuser@<VM_PUBLIC_IP>

11. The Cost Trap: "Stopped" vs. "Stopped (Deallocated)"

⚠️ Critical Billing Rule: If you shut down the VM from inside Ubuntu (sudo shutdown now), Azure marks the VM as Stopped, NOT deallocated. Microsoft still holds physical hardware reserved for you and continues billing your CPU and RAM every minute!
Action Taken Status in Azure Portal Compute (CPU/RAM) Billing Disk Storage Billing
Guest OS Shutdown Stopped 💸 STILL BILLED! 💸 Billed
Azure Portal Stop Button Stopped (deallocated) 🛑 ₹0 / $0 (COMPUTE FREE) 💸 Minor disk only (~cents)

Always click STOP in the Azure Portal (or run az vm deallocate) when you finish studying!

12. Clean Lab Teardown Protocol ($0 Bill Guarantee)

Because all resources were created inside the azure-vm-rg Resource Group, you can delete everything in one single action:

  1. In the Azure Portal search bar, type Resource groups → click on azure-vm-rg.
  2. In the top action bar, click Delete resource group.
  3. Type azure-vm-rg into the confirmation field → click Delete.
  4. Azure cleanly destroys the VM, OS disk, public IP, NIC, and virtual network together.
