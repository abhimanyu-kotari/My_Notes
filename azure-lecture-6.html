Azure Blob Storage

What is this module about? Microsoft's massively scalable object storage solution: storing terabytes of unstructured photos, videos, backups, and ML datasets. Understanding storage account hierarchy, naming constraints, Block vs. Append vs. Page Blobs, Hot/Cool/Cold/Archive tiers and rehydration, 11 to 16 nines of durability redundancy, time-limited SAS tokens, and hosting free static websites from the $web container.
Why is this critical for engineers? High-scale apps, AI training pipelines, and data lakes never store multi-gigabyte media inside SQL databases. Blob storage is the foundational data reservoir of the cloud.

01. What is Azure Blob Storage?

Relational SQL databases are optimized for structured rows and columns. They degrade quickly when forced to store 500 MB video files or millions of PDF receipts.

Azure Blob Storage is Microsoft's massively scalable Object Storage engine.
- "BLOB" stands for Binary Large OBject.
- Stores any digital file in native binary format without requiring you to format hard disks or partition file systems.
- Every blob is directly addressable anywhere on earth via standard HTTPS REST URLs.

02. The Amazon Warehouse Analogy & Naming Rules

The Logistics Warehouse:

- Storage Account: The entire Amazon distribution building with its unique global address.
- Container: An organized aisle or storage bin (e.g., avatars, invoices, videos).
- Blob: The packaged items inside the container (e.g., user-102.png, tax-2026.pdf).

URL Format: https://<storage-account-name>.blob.core.windows.net/<container-name>/<blob-name> Example: https://mystorageak2026.blob.core.windows.net/images/profile.jpg
⚠️ The 3 Inviolable Storage Account Naming Rules:
  1. Length must be strictly between 3 and 24 characters.
  2. Contains ONLY lowercase letters and numbers (No hyphens, no underscores, no uppercase!).
  3. Must be globally unique across all Azure accounts worldwide because it creates a public DNS subdomain.

03. The 3 Types of Blobs

Blob Type Primary Purpose Maximum Size Key Behavior
Block Blobs Documents, photos, videos, zip archives, application files. ~190.7 TB Composed of up to 50,000 discrete blocks uploaded in parallel and assembled.
Append Blobs Server access logs, telemetry streams, audit trails. ~195 GB Append-only operations. Existing data cannot be edited; new logs are committed to the end.
Page Blobs Azure VM Hard Disks (.vhd files). 8 TB Optimized for 512-byte random read/write page operations like a physical hard disk.

04. Access Tiers & Rehydration

Azure matches storage costs to how frequently your files are accessed:

+-----------+-------------------------+--------------+-----------------------+ | Tier | Access Frequency | Storage Cost | Access/Retrieval Cost | +-----------+-------------------------+--------------+-----------------------+ | Hot | Daily active usage | Highest | Lowest | | Cool | Infrequent (30+ days) | Lower | Higher | | Cold | Rarely accessed (90+) | Very Low | Much Higher | | Archive | Long-term backup (180+) | Rock Bottom | Highest (Must Rehydrate)| +-----------+-------------------------+--------------+-----------------------+
🧊 The Archive Tier & Rehydration: Blobs in Archive tier are stored offline. You cannot download them immediately. To read an archived blob, you must Rehydrate it back to Hot or Cool:
  • Standard Priority: Takes 1 to 15 hours.
  • High Priority: Takes under 1 hour (for files < 10 GB) with an extra urgency fee.

05. Data Redundancy: 11 to 16 Nines of Durability

  • Locally Redundant Storage (LRS): 3 copies maintained in a single datacenter in the primary region. Protects against disk crashes. Durability: 99.999999999% (11 9s).
  • Zone-Redundant Storage (ZRS): 3 copies replicated synchronously across 3 separate Availability Zones in the primary region. Protects against entire datacenter fires. Durability: 99.9999999999% (12 9s).
  • Geo-Redundant Storage (GRS): LRS in primary region + asynchronously copied to a paired secondary region >300 miles away (total 6 copies). Protects against regional natural disasters. Durability: 16 9s.
  • Geo-Zone-Redundant Storage (GZRS): ZRS in primary region across 3 zones + LRS in secondary paired region. The ultimate high-durability standard.

06. Security: Storage Keys vs. Shared Access Signatures (SAS)

How do applications access files securely?

1. Account Access Keys (Key 1 & Key 2): - Master root passwords with unrestricted 100% control over the entire storage account. - NEVER commit these keys to GitHub or embed them inside mobile apps! 2. Shared Access Signatures (SAS Tokens): - Secure, temporary digital pass tickets. - Example: "Allow user Alice to READ only 'invoice.pdf' until 5:00 PM today from IP 192.168.1.5."

07. Hosting a Serverless Static Website ($web container)

You can host an entire production website directly from Blob Storage for pennies a month without running any web servers or VMs:

# Step-by-Step Hands-On: 1. Open your Storage Account in Azure Portal. 2. In left sidebar, click "Static website" (under Data management). 3. Select "Enabled". 4. Set Index document name: "index.html". 5. Set Error document path: "404.html" → Click Save. 6. Azure creates a special container named "$web" and gives you a public URL! 7. Upload your index.html and style.css into the "$web" container. 8. Visit the endpoint URL in your browser: Your website is live on the internet!

08. Automated Lifecycle Management

Azure allows you to write automated rules to save storage costs automatically:

Rule: Move to Cool after 30 days → Move to Archive after 90 days → Delete after 365 days

09. Azure CLI Cheatsheet for Blob Storage

# 1. Create a Storage Account az storage account create \ --name mystorageak2026 \ --resource-group my-rg \ --location eastus \ --sku Standard_LRS # 2. Create a Container az storage container create \ --account-name mystorageak2026 \ --name media-uploads \ --auth-mode login # 3. Upload a Blob file az storage blob upload \ --account-name mystorageak2026 \ --container-name media-uploads \ --name hero.png \ --file ./images/hero.png \ --auth-mode login # 4. Generate a 1-Hour Read-Only SAS Token az storage blob generate-sas \ --account-name mystorageak2026 \ --container-name media-uploads \ --name hero.png \ --permissions r \ --expiry $(date -u -d "1 hour" '+%Y-%m-%dT%H:%MZ') \ --full-uri
