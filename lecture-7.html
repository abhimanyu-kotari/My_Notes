File Input & Output (I/O) in Python

What is this topic? File I/O (Input/Output) is how Python reads information from and writes information into files (like .txt or .csv) saved on your computer's hard drive or SSD.
Why do we use it? Regular Python variables disappear the moment your program closes because they only live in temporary memory (RAM). We use File I/O whenever data must be saved permanently—like saving a player's high score, keeping user accounts, writing daily activity logs, or reading records from a document.

01. Why Do We Need Files? (RAM vs. Permanent Storage)

1. The Problem with Normal Variables

So far in our Python journey, whenever we created a variable like name = "Alice" or score = 100, where was that data stored?

It was stored in your computer's RAM (Random Access Memory). RAM is lightning-fast, but it has one big catch: it is temporary (volatile).

Real-Life Analogy: The Classroom Blackboard vs. A Notebook

Think of RAM like a teacher's blackboard. During a lecture, the teacher writes notes, calculations, and formulas on the board. Everything is quick and accessible. But as soon as class ends, the board is wiped clean! When your Python program finishes running or you turn off your computer, everything in RAM disappears.

If you want notes to stay with you tomorrow, next week, or next year, you write them in your notebook. In computer terms, that notebook is a File saved on your hard drive or SSD (secondary storage)!

2. What is a File?

A File is simply a named collection of data stored permanently on your disk (SSD or HDD).

  • Without files: If you build a game, the player's high score is lost the second they close the game window.
  • With files: Your game writes high_score = 950 into a file named saved_game.txt. When the player opens the game next week, the program reads the file and restores their score!
RAM (Memory)

Super fast • Temporary • Data is lost when program stops

→ Save to →
Files (Disk / SSD)

Permanent storage • Safe • Data stays even when PC shuts down

The operations we perform on files—reading data from them (Input) and writing data into them (Output)—are called File I/O (Input / Output).

02. Types of Files: Text Files vs. Binary Files

In everyday programming, files broadly fall into two friendly categories:

Type What is inside? Common Examples Can you open it in Notepad?
1. Text Files Plain human-readable characters, words, sentences, and numbers. .txt, .py, .csv, .json, .log Yes! Looks like normal text.
2. Binary Files Special computer-encoded raw data (media, images, audio, compiled code). .png, .jpg, .mp4, .pdf, .exe No. Opens as strange unreadable symbols and gibberish.
Quick Fun Fact: All Files are 0s and 1s!

Behind the scenes, your computer stores both text files and binary files as combinations of 0s and 1s (bits). The only difference is that for a text file, your computer translates those 0s and 1s into letters (like 'A', 'B', 'C') using character sets like UTF-8 or ASCII!

03. 3 Simple Steps: open(), Read/Write, close()

Working with files in Python is as easy as 1-2-3:

  1. Open the file: Tell Python which file you want to work with and what you want to do (read or write).
  2. Perform your action: Read data out of it, or write new data into it.
  3. Close the file: Pack up and close the file so your computer saves the changes and frees up memory.
python 
# Step 1: Open the file in read mode ("r")
f = open("demo.txt", "r")

# Step 2: Read the contents into a variable
data = f.read()
print(data)

# Step 3: Always close the file when finished!
f.close()

How the open() Function Works

The open() function takes two arguments:

f = open("file_name", "mode")
  • file_name: The name (or path) of the file you want to open (e.g. "demo.txt").
  • mode: What you plan to do. For example, "r" for reading or "w" for writing.
  • Default Mode: If you don't write the second argument, Python defaults to "r" (read mode)!
    So open("demo.txt") is exactly the same as open("demo.txt", "r").

Why Must We Call f.close()?

Imagine taking a book from a library shelf. While you have it on your desk, nobody else can check it out. If you walk away without putting it back, it stays locked up!

  • Closing a file tells the computer: "I am done with this file. Please save all changes to disk and let other programs use it."
  • If you forget to close files in big programs, your computer can run out of file handles or lose unsaved changes!

04. File Modes Made Simple ('r', 'w', 'a', 'x')

When opening a file, the mode tells Python your intention. Here are the 4 main modes every beginner should know:

Mode Meaning What if the file exists? What if the file is MISSING? Simple Analogy
'r' Read (Default) Opens it for reading. Does not touch or change existing content. Gives an Error! (FileNotFoundError) Opening a textbook to read. If you don't own the book, you can't read it!
'w' Write (Overwrite) Erases everything! Wipes the file completely clean to start fresh. Creates a new file automatically. Erasing a whiteboard completely before writing new notes.
'a' Append (Add to end) Keeps all existing text! Moves your cursor to the very bottom so new lines are added at the end. Creates a new file automatically. Adding a new diary entry at the end of your diary without tearing out old pages.
'x' Create (Exclusive) Gives an Error! (FileExistsError) Creates a brand new file for writing. Creating a new username. Fails if the name is already taken!
python 
# Example 1: Trying to read a file that doesn't exist
try:
    f = open("missing_notes.txt", "r")
except FileNotFoundError:
    print("Oops! File does not exist, so 'r' mode raises an error!")

# Example 2: In 'w' mode, Python automatically creates the file for you!
f = open("new_file.txt", "w")
f.write("Hello, World!\n")
f.close()
print("new_file.txt was created and written successfully!")

05. Reading Files & The Bookmark Analogy

1. The File Cursor (Your Reading Finger)

Whenever Python opens a file, it keeps track of a cursor (or pointer).

The Finger / Bookmark Analogy

Imagine reading a physical book with your index finger pointing to each word as you read:

  • When you open the book, your finger is at letter 0 (the start).
  • If you read 5 letters, your finger moves forward by 5 letters.
  • If you read the whole book from start to finish, your finger reaches the very last page (EOF — End of File).

2. The 3 Ways to Read Data

python 
# Suppose demo.txt contains:
# Line 1: Python is easy.
# Line 2: We love coding.

# --- METHOD 1: f.read() reads the ENTIRE file at once ---
f = open("demo.txt", "r")
all_text = f.read()
print(all_text)
f.close()

# --- METHOD 2: f.read(n) reads only 'n' characters ---
f = open("demo.txt", "r")
first_six = f.read(6)   # Reads first 6 characters -> "Python"
print("First 6 chars:", first_six)
f.close()

# --- METHOD 3: f.readline() reads ONE line at a time ---
f = open("demo.txt", "r")
line_one = f.readline()  # Reads up to the first newline '\n'
line_two = f.readline()  # Reads the next line
print("1st line:", line_one, end="")
print("2nd line:", line_two, end="")
f.close()

3. Why Does readline() Return Nothing After read()?

This is the #1 most common mistake beginners make:

python 
f = open("demo.txt", "r")

data = f.read()       # Reads the WHOLE file. Cursor is now at the END!
print(data)

line = f.readline()   # Output is EMPTY: "" ! Why?
print("Line is:", repr(line))  # Prints: ''
f.close()

Why did that happen?
Because f.read() already moved your reading finger all the way to the very end of the file! There is nothing left after the end of the file.

How to fix it:
If you want to read again from the top, you can either close and reopen the file, or use f.seek(0) to move your finger back to the start!

06. Writing vs. Appending Data

1. The Overwrite Danger of 'w'

Whenever you open an existing file in "w" mode, Python immediately deletes all previous content in that file. It clears the slate so you can write from scratch.

python 
# Suppose demo.txt had 100 lines of old notes.
f = open("demo.txt", "w")

# The 100 old lines are now completely wiped clean!
f.write("This is my brand new line.\n")
f.close()
# demo.txt now contains ONLY this one new line.

2. Keeping Old Data Safe with 'a' (Append)

If you want to add new lines without erasing old lines, use "a" (append mode):

python 
# 'a' mode leaves old text untouched and adds new text at the end!
f = open("demo.txt", "a")
f.write("Here is an extra line at the bottom.\n")
f.close()
Important Tip: write() Does NOT Add Newlines Automatically

When you use print("hello"), Python automatically jumps to the next line.

But f.write("hello") does NOT add a new line! If you write:
f.write("Hello")
f.write("World")
Your file will look like HelloWorld stuck together! If you want separate lines, always add \n:
f.write("Hello\n")

07. The '+' Modes Explained ('r+', 'w+', 'a+')

Sometimes you want to both read AND write to a file at the same time. In Python, adding a + gives you both abilities!

Mode Can Read? Can Write? Does it erase existing content? How it works in plain English
'r+' Yes Yes No (Safe!) Starts at the beginning. If you write, it overwrites letter-by-letter from the start without deleting the rest.
'w+' Yes Yes Yes (Wipes clean!) Empties the whole file first! Then lets you write, and you can also read what you wrote.
'a+' Yes Yes No (Safe!) Lets you read, and any writes are automatically pasted at the very end of the file.

How 'r+' Overwrites (Letter-by-Letter)

Suppose your file contains the word "abcdef":

python 
# Initial file content: "abcdef"
f = open("sample.txt", "r+")

# We write 3 characters "123" at position 0
f.write("123")
f.close()

# Final file content: "123def"
# Notice: Only the first 3 letters ('a','b','c') were replaced with '1','2','3'.
# The remaining 'def' was untouched!

08. The 'with' Syntax: The Automatic Closer

1. The Smart Way to Handle Files

What happens if your program crashes or encounters an error before reaching f.close()? The file remains open and locked in memory!

To make life easy, Python provides the with statement. Think of it like an automatic door closer:

python 
# The Pythonic Way: Using 'with'
with open("demo.txt", "r") as f:
    data = f.read()
    print(data)
    # We do NOT need to write f.close()!

# As soon as we leave the indented block, Python closes the file automatically!
print("Is file closed?", f.closed)  # True!
Why 'with' is Loved by All Python Developers
  • Zero Stress: You never have to worry about forgetting f.close().
  • Error Proof: Even if your code throws an error inside the block, Python guarantees the file is safely closed.
  • Cleaner Code: Shorter, simpler, and matches industry best practices.

09. Deleting Files & The os Module

1. How to Delete a File in Python

You might wonder: Does Python have a f.delete() function?
No! Deleting a file is an Operating System action (like right-clicking a file and choosing "Delete").

So to delete a file, we use Python's built-in os (Operating System) module:

python 
import os

# Deletes the file permanently from your disk
os.remove("sample.txt")
print("sample.txt has been deleted!")

2. Built-in Modules vs. External Packages (pip)

This is an important distinction you will hear in interviews:

  • Built-in Modules (e.g. os, math, random):
    These are like pre-installed apps on a brand-new smartphone (like the Calculator or Clock). They come packaged with Python. You don't need the internet or any installation commands—just write import os!
  • External Modules (e.g. tensorflow, numpy, pandas):
    These are like apps from the App Store / Play Store. They are written by other developers. You must download and install them using the terminal command:
    pip install tensorflow

Practice Problem 4: Find Which Line Contains the Word

Line Finder

Task: Write a function check_for_line(word) that finds which line number the word first appears on (1, 2, 3...). If it is not found, return -1.

python 
# Solution to Problem 4: Read line-by-line using a while loop
def check_for_line(word):
    line_number = 1
    with open("practice.txt", "r") as f:
        while True:
            line = f.readline()
            
            # If line is empty string "", we reached the end of the file!
            if not line:
                break
            
            if word in line:
                print(f"Found '{word}' on Line {line_number}!")
                return line_number
            
            line_number += 1

    print(f"'{word}' was not found in any line.")
    return -1

check_for_line("learning")  # Found 'learning' on Line 2!
check_for_line("Python")    # Found 'Python' on Line 3!
check_for_line("Banana")    # 'Banana' was not found in any line. Returns -1.

Practice Problem 5: Count Even Numbers in a Comma-Separated File

Numbers Parsing

Task: From a file named numbers.txt containing comma-separated numbers (like 1, 2, 45, 55, 86, 76), parse all numbers and count how many of them are even numbers.

python 
# Step 1: Create the numbers.txt file
with open("numbers.txt", "w") as f:
    f.write("1, 2, 45, 55, 86, 76")

# Step 2: Read and count even numbers
with open("numbers.txt", "r") as f:
    data = f.read()

# split(",") separates the string wherever a comma appears
# Result: ['1', ' 2', ' 45', ' 55', ' 86', ' 76']
numbers_list = data.split(",")
even_count = 0

for val in numbers_list:
    num = int(val.strip())  # strip() removes extra spaces, int() converts to number
    if num % 2 == 0:
        even_count += 1
        print(f"Even number found: {num}")

print(f"Total even numbers count: {even_count}")  # Output: 3 (2, 86, 76)

11. Quick Reference & Summary Matrix

Keep this summary handy whenever you are writing file handling code:

Mode Action If file exists If file is missing Where does writing start?
'r' Read only Safe (reads content) Error (FileNotFoundError) Cannot write
'w' Write only Wipes it clean to 0 Creates new file At the very start (0)
'a' Append only Safe (keeps old data) Creates new file At the end (EOF)
'r+' Read & Write Safe (keeps old data) Error Overwrites from cursor forward
'w+' Read & Write Wipes it clean to 0 Creates new file At the very start (0)
'a+' Read & Write Safe (keeps old data) Creates new file Always at the end (EOF)
