Object-Oriented Programming (Part 2): Inheritance & Polymorphism

What is this topic? Object-Oriented Programming (Part 2) covers advanced OOP tools: deleting data with del, protecting sensitive data with private members (__), reusing and extending code across classes using Inheritance, calling parent constructors with super(), managing class-level data with @classmethod, computing live values with @property, and implementing Polymorphism via operator overloading (like __add__ and __gt__).
Why do we use it? We use these tools to build secure, scalable, and intuitive software—safeguarding confidential passwords from accidental changes, avoiding duplicate code across related classes, keeping calculated attributes automatically synchronized, and making custom objects interact cleanly using familiar math symbols like + and >.

01. The del Keyword: Deleting Attributes & Objects

1. What is the del Keyword?

In Python, the del keyword is used to delete object properties (attributes) or entire objects themselves. When an object is deleted, its name binding is severed from memory. If no other variable points to that object, Python's automatic garbage collector safely frees that memory.

Operation Python Syntax What Happens Internally? Accessing Afterwards
Delete Attribute del s1.name Removes the specific property name from the object's instance dictionary. Raises AttributeError: 'Student' object has no attribute 'name'
Delete Entire Object del s1 Unbinds variable s1. Object memory is marked for garbage collection. Raises NameError: name 's1' is not defined

2. Code Example: Deleting Object Properties and Instances

Let's see how del behaves when applied to an attribute versus an entire object:

python 
class Student:
    def __init__(self, name):
        self.name = name

# Create student object
s1 = Student("Karan")
print(s1.name)   # Output: Karan

# Case 1: Delete an object's attribute
del s1.name
# print(s1.name)  # → AttributeError: 'Student' object has no attribute 'name'

# Case 2: Delete the entire object
del s1
# print(s1)       # → NameError: name 's1' is not defined
Important Takeaway: Deletion vs. Reassignment

Writing s1.name = None does not delete the attribute; the attribute still exists and simply holds None. In contrast, del s1.name completely removes the attribute key from the object, so checking for it will throw an AttributeError.

02. Private Attributes & Methods (__ Double Underscore)

1. Public vs. Private: Conceptual Need for Data Protection

By default in Python, all attributes and methods inside a class are Public. This means any code outside the class can read and modify them directly (e.g., acc1.balance = 0).

In production software, some sensitive data (like passwords, secret keys, or internal bank balances) must be protected from accidental modification or direct external exposure. Python provides a mechanism to make attributes and methods Private.

Public Attributes & Methods

Accessible from anywhere: inside the class methods AND outside the class using object.attr.

self.acc_no = 12345
acc.display()
Private Attributes & Methods (__)

Accessible only inside the class. Direct external access throws an AttributeError.

self.__acc_pass = "secret"
acc.__reset() # ERROR outside!

2. Syntax: Two Leading Underscores (__)

To make any attribute or method private in Python, prefix its name with two underscores (__):

python 
class Account:
    def __init__(self, acc_no, acc_pass):
        self.acc_no = acc_no          # Public attribute
        self.__acc_pass = acc_pass    # Private attribute (prefixed with __)

    # Public method can read private attributes internally
    def reset_password(self):
        print("Internal Password access:", self.__acc_pass)

acc1 = Account("12345", "abcde")

print(acc1.acc_no)         # Output: 12345 (Public is accessible)
acc1.reset_password()      # Output: Internal Password access: abcde

# Attempting direct outside access will crash:
# print(acc1.__acc_pass)   # → AttributeError: 'Account' object has no attribute '__acc_pass'

3. Private Methods in Action

Methods can also be made private using def __method_name(self):. These methods are designed as internal helper routines that other methods inside the class use, but external callers cannot call:

python 
class Person:
    def __hello(self):                # Private method
        print("Hello, internal person!")

    def welcome(self):                # Public method
        self.__hello()                # Calls private helper internally

p1 = Person()
p1.welcome()                          # Output: Hello, internal person!

# Direct call outside raises AttributeError:
# p1.__hello()                        # → AttributeError: 'Person' object has no attribute '__hello'
Behind the Scenes: Name Mangling

Python doesn't have true C++ or Java hardware-level privacy. Instead, it performs Name Mangling: an attribute named __acc_pass inside class Account is internally renamed by Python to _Account__acc_pass.

While you technically could write acc1._Account__acc_pass, this is strongly discouraged. The __ prefix serves as an explicit contract to developers: "This is internal private state—do not touch it directly!"

03. Inheritance: Single, Multi-level & Multiple

1. What is Inheritance? (The 3rd Pillar of OOP)

Inheritance is the mechanism where one class (called the Child or Derived class) acquires all the properties (attributes) and behaviors (methods) of another class (called the Parent or Base class).

Terminology Alternative Names Role in Hierarchy Example
Base Class Parent Class, Super Class The original class providing common attributes and methods. class Car:
Derived Class Child Class, Sub Class The new class that inherits and reuses the parent's logic, adding its own specializations. class ToyotaCar(Car):
Why Use Inheritance? The DRY Principle (Don't Repeat Yourself)

Imagine building a software platform for vehicles: ToyotaCar, BMW, Tesla, and Ferrari. All of them have a color, can start(), and can stop().

Instead of copying and pasting the same start() and stop() methods across 20 different car classes, we write them once in a general Car parent class. Every specific car model inherits them automatically!

2. The Three Types of Inheritance in Python

Python supports three fundamental forms of inheritance:

1. Single Inheritance

A single derived class inherits from a single base class.

Base (Car)
↓
Derived (ToyotaCar)
2. Multi-Level Inheritance

A chain where Class B inherits from Class A, and Class C inherits from Class B.

Grandparent (Car)
↓
Parent (ToyotaCar)
↓
Child (Fortuner)
3. Multiple Inheritance

A single derived class inherits from two or more independent base classes simultaneously.

Parent A  +  Parent B
↓
Child C(A, B)

3. Type 1: Single Inheritance Implementation

Let's implement single inheritance with Car and ToyotaCar:

python 
# Base Class
class Car:
    color = "black"

    @staticmethod
    def start():
        print("car started..")

    @staticmethod
    def stop():
        print("car stopped.")

# Derived Class inheriting Car
class ToyotaCar(Car):
    def __init__(self, name):
        self.name = name

car1 = ToyotaCar("Fortuner")
car2 = ToyotaCar("Prius")

print(car1.name)   # Output: Fortuner (from ToyotaCar)
print(car1.color)  # Output: black (inherited from Car)
car1.start()       # Output: car started.. (inherited from Car)
car1.stop()        # Output: car stopped. (inherited from Car)

4. Type 2: Multi-Level Inheritance Implementation

In multi-level inheritance, properties cascade down an entire family tree:

python 
class Car:
    @staticmethod
    def start():
        print("car started..")

    @staticmethod
    def stop():
        print("car stopped.")

class ToyotaCar(Car):
    def __init__(self, brand):
        self.brand = brand

class Fortuner(ToyotaCar):
    def __init__(self, type):
        self.type = type

car1 = Fortuner("diesel")
print(car1.type)   # Output: diesel
car1.start()       # Output: car started.. (inherited all the way from Car!)

5. Type 3: Multiple Inheritance Implementation

In multiple inheritance, a child class combines traits from multiple independent parent classes:

python 
class A:
    varA = "welcome to class A"

class B:
    varB = "welcome to class B"

# Class C inherits from both A and B
class C(A, B):
    varC = "welcome to class C"

c1 = C()
print(c1.varA)  # Output: welcome to class A (from class A)
print(c1.varB)  # Output: welcome to class B (from class B)
print(c1.varC)  # Output: welcome to class C (from class C)

04. The super() Method (Parent Class Access)

1. Why Do We Need super()?

When a child class defines its own __init__() constructor, it overrides the parent class's constructor. This means the parent's initialization code will not run unless we explicitly call it!

The super() method is a built-in Python function used to access and call methods of the parent class directly from within the child class.

python 
class Car:
    def __init__(self, type):
        self.type = type

    def start(self):
        print("car started..")

    def stop(self):
        print("car stopped.")

class ToyotaCar(Car):
    def __init__(self, name, type):
        self.name = name
        # Call the parent class constructor to set self.type!
        super().__init__(type)
        # We can also invoke parent methods using super():
        super().start()

# Instantiate ToyotaCar
car1 = ToyotaCar("Prius", "electric")
# Output during instantiation: car started..

print(car1.name)  # Output: Prius
print(car1.type)  # Output: electric (successfully initialized via super()!)
Key Rules for Using super()
  • No need to pass self: When calling super().__init__(type), Python automatically handles the self pointer for you.
  • Constructor chaining: Always call super().__init__() when the child class adds new attributes on top of the parent's base attributes.
  • Method reuse: You can call any parent method via super().method_name(), which is especially useful if the child method overrides it and wants to extend rather than replace it.

05. Class Methods (@classmethod) vs. Instance vs. Static

1. The 3 Method Types in Python

In Python, methods inside a class can belong to an individual object instance, to the class blueprint itself, or act as an independent utility. Understanding their differences is key to mastering OOP:

Method Type Decorator First Parameter What Does It Access? Typical Purpose
Instance Method None (default) self Individual object's instance attributes (self.name). Perform actions on specific object state.
Class Method @classmethod cls The class object itself (cls.attribute). Modify class-level attributes, alternative factory constructors.
Static Method @staticmethod None (no self or cls) Neither instance nor class state directly. Utility / helper functions logically grouped within the class.

2. The Problem: Modifying a Class Attribute from Inside a Method

Suppose we have a class-level attribute name = "anonymous". If we define a normal method and write self.name = name, Python creates a new instance attribute named name rather than modifying the shared class attribute!

python 
class Person:
    name = "anonymous"

    def changeName(self, name):
        self.name = name  # Warning: Creates instance attribute! Class attribute unchanged!

p1 = Person()
p1.changeName("Rahul Kumar")
print(p1.name)      # Output: Rahul Kumar (instance attribute)
print(Person.name)  # Output: anonymous (class attribute stayed the same!)

3. The Solution: Using @classmethod

By decorating the method with @classmethod and using cls as the first parameter, we bind the method directly to the class itself:

python 
class Person:
    name = "anonymous"

    @classmethod
    def changeName(cls, name):
        cls.name = name   # Directly updates the class-level attribute!

p1 = Person()
p1.changeName("Rahul Kumar")

print(p1.name)      # Output: Rahul Kumar
print(Person.name)  # Output: Rahul Kumar (successfully updated at class level!)
3 Ways to Change Class Attributes (And Why @classmethod is Best)

As discussed in the lecture, there are three ways to modify a class attribute:

  1. Person.name = name — Hardcodes the class name. If the class is renamed or subclassed, this breaks.
  2. self.__class__.name = name — Works, but looks verbose and obscure.
  3. @classmethod def changeName(cls, name): cls.name = name — The Pythonic Standard! Clean, elegant, and automatically works with inheritance.

06. The @property Decorator (Dynamic Attributes)

1. The Stale Data Problem

Consider a Student class with marks in Physics, Chemistry, and Mathematics, plus an attribute calculating their percentage:

python 
class Student:
    def __init__(self, phy, chem, math):
        self.phy = phy
        self.chem = chem
        self.math = math
        self.percentage = str((self.phy + self.chem + self.math) / 3) + "%"

stu1 = Student(98, 97, 99)
print(stu1.percentage)  # Output: 98.0%

# Teacher accidentally entered wrong physics marks and corrects it:
stu1.phy = 86
print(stu1.percentage)  # Output STILL 98.0%! (STALE / OUT-OF-DATE DATA!)

2. The Solution: The @property Decorator

We use the @property decorator on any method in the class to use that method as a property. Whenever you access student.percentage, Python automatically calls the method in the background and computes the fresh, live value on the fly without needing parentheses ()!

python 
class Student:
    def __init__(self, phy, chem, math):
        self.phy = phy
        self.chem = chem
        self.math = math

    @property
    def percentage(self):
        # Dynamically calculated every time stu1.percentage is accessed!
        return str((self.phy + self.chem + self.math) / 3) + "%"

stu1 = Student(98, 97, 99)
print(stu1.percentage)  # Output: 98.0%

stu1.phy = 86          # Modify physics marks
print(stu1.percentage)  # Output: 94.0%! (Automatically updated and synced!)
Getters and Setters

In Python, the @property decorator acts as a Getter. You can also define a companion Setter using @property_name.setter to perform validation or execute actions when someone assigns a value to that property (e.g. stu1.percentage = "95%").

07. Polymorphism & Operator Overloading (__add__, etc.)

1. What is Polymorphism? (The 4th Pillar of OOP)

The word Polymorphism is derived from Greek: Poly (many) + Morph (forms). It means the ability of an operator, function, or method to take on multiple forms depending on the context or data types provided.

Everyday Polymorphism: The '+' Operator

You have already been using polymorphism in Python from Day 1:

  • 1 + 2 = 3 — With integers, + performs Arithmetic Addition.
  • "apna" + "college" = "apnacollege" — With strings, + performs Concatenation.
  • [1, 2] + [3, 4] = [1, 2, 3, 4] — With lists, + performs List Merging.

The same operator + exhibits completely different behaviors based on the underlying object type!

2. What are Dunder (Magic) Methods?

How does Python know what to do when you write a + b? Behind the scenes, Python translates operators into special methods surrounded by double underscores, commonly called Dunder Methods or Magic Methods.

Writing a + b is syntactic sugar for a.__add__(b)!

Operator Operation Underlying Dunder Method Expression Translation
+ Addition __add__(self, other) a + b → a.__add__(b)
- Subtraction __sub__(self, other) a - b → a.__sub__(b)
* Multiplication __mul__(self, other) a * b → a.__mul__(b)
/ Division __truediv__(self, other) a / b → a.__truediv__(b)
% Modulo (Remainder) __mod__(self, other) a % b → a.__mod__(b)
> Greater Than __gt__(self, other) a > b → a.__gt__(b)
< Less Than __lt__(self, other) a < b → a.__lt__(b)
== Equality __eq__(self, other) a == b → a.__eq__(b)

3. Real Implementation: Custom Complex Number Class with __add__ & __sub__

In mathematics, a complex number has a real part and an imaginary part: $a + bi$. By default, writing num1 + num2 on custom objects causes a TypeError: unsupported operand type(s) for +. By overloading __add__ and __sub__, we make Python understand custom addition and subtraction!

python 
class Complex:
    def __init__(self, real, img):
        self.real = real
        self.img = img

    def showNumber(self):
        print(str(self.real) + "i + " + str(self.img) + "j")

    # Overloading the + operator
    def __add__(self, num2):
        newReal = self.real + num2.real
        newImg = self.img + num2.img
        return Complex(newReal, newImg)

    # Overloading the - operator
    def __sub__(self, num2):
        newReal = self.real - num2.real
        newImg = self.img - num2.img
        return Complex(newReal, newImg)

num1 = Complex(1, 3)    # 1i + 3j
num1.showNumber()

num2 = Complex(4, 6)    # 4i + 6j
num2.showNumber()

# Adding two complex numbers using + (triggers __add__)
num3 = num1 + num2
num3.showNumber()       # Output: 5i + 9j

# Subtracting two complex numbers using - (triggers __sub__)
num4 = num1 - num2
num4.showNumber()       # Output: -3i + -3j

08. Practice 1: Circle Class (Area & Perimeter)

Problem Statement

Define a Circle class to create a circle with radius $r$ using the constructor.
Define an area() method of the class which calculates the area of the circle ($A = \pi r^2$).
Define a perimeter() method of the class which allows you to calculate the perimeter of the circle ($P = 2 \pi r$). Use $\pi = rac{22}{7}$ or $3.14$.

Step-by-Step Implementation

We initialize the circle with its radius $r$ in __init__, and compute the geometric values using mathematical formulas:

python 
class Circle:
    def __init__(self, radius):
        self.radius = radius

    def area(self):
        # Formula: π * r^2
        return (22 / 7) * self.radius ** 2

    def perimeter(self):
        # Formula: 2 * π * r
        return 2 * (22 / 7) * self.radius

# Test with radius = 21
c1 = Circle(21)
print("Radius:", c1.radius)
print("Area:", c1.area())            # Output: 1386.0
print("Perimeter:", c1.perimeter())  # Output: 132.0

09. Practice 2: Employee & Engineer Hierarchy

Problem Statement

Define an Employee class with attributes role, department, and salary. Create a showDetails() method for it.
Now create an Engineer class that inherits properties from Employee and has additional attributes: name and age. Use super() to initialize the parent employee properties.

Step-by-Step Implementation

We construct the base Employee class and extend it into the specialized Engineer class, chaining the constructors with super():

python 
# Base Class
class Employee:
    def __init__(self, role, dept, salary):
        self.role = role
        self.dept = dept
        self.salary = salary

    def showDetails(self):
        print("Role:", self.role)
        print("Dept:", self.dept)
        print("Salary:", self.salary)

# Derived Class
class Engineer(Employee):
    def __init__(self, name, age):
        self.name = name
        self.age = age
        # Initialize base Employee properties via super()
        super().__init__("Engineer", "IT", "75,000")

eng1 = Engineer("Elon Musk", 40)
print("Name:", eng1.name)
print("Age:", eng1.age)
eng1.showDetails()
output 
Name: Elon Musk
Age: 40
Role: Engineer
Dept: IT
Salary: 75,000

10. Practice 3: Order Class with __gt__ Overloading

Problem Statement

Create an Order class which stores item and its price.
Use Dunder method __gt__() to convey that order1 > order2 if the price of order1 is greater than the price of order2.

Step-by-Step Implementation

We implement the Order class and overload the greater-than comparison operator (>) using __gt__(self, other):

python 
class Order:
    def __init__(self, item, price):
        self.item = item
        self.price = price

    # Overloading the greater-than (>) comparison operator
    def __gt__(self, order2):
        return self.price > order2.price

order1 = Order("chips", 20)
order2 = Order("tea", 15)

print(order1 > order2)  # Output: True (since 20 > 15)
print(order2 > order1)  # Output: False (since 15 is not > 20)
Why Operator Overloading Creates Clean Code

Without operator overloading, developers are forced to write awkward function calls like order1.is_greater_than(order2) or access raw internals everywhere like order1.price > order2.price.

Overloading __gt__ makes your custom domain objects behave as first-class citizens in Python, enabling sorting via sorted([order1, order2]) and comparisons using clean, readable mathematical syntax.
