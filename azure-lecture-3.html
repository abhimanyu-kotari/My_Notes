Docker & Containerization Basics

What is this module about? The revolutionary technology that changed modern software delivery: why Docker solves the dreaded "It works on my machine!" problem, how containers share the host operating system kernel to achieve featherweight megabyte sizes and sub-second boot times, writing clean Dockerfiles, and mastering the Docker CLI.
Why is this critical for engineers? You cannot do modern cloud computing without containers. Azure Container Instances (ACI), Azure Container Apps (ACA), and Azure Kubernetes Service (AKS) all package and deploy applications as Docker container images.

01. The "It Works on My Machine!" Crisis

Every software engineer knows this infamous story:

A developer writes a Python web application on their MacBook. Everything runs smoothly. They push the code to production or hand it to the QA testing team running Windows or Linux. Instantly, the app crashes with runtime errors!

Why did it fail? Environment Drift!
  • Mac had Python 3.11 installed; production had Python 3.8.
  • Mac had local environment variables pre-configured.
  • A system C-library (e.g. libpq-dev for PostgreSQL) was missing on the server.

Docker eliminates this entire crisis forever by packaging the application code, the exact runtime, system libraries, configuration files, and dependencies into a single, immutable, self-contained unit called a Container.

02. Virtual Machines vs. Containers

+------------------------------------+ +------------------------------------+ | VIRTUAL MACHINES (VMs) | | DOCKER CONTAINERS | +------------------------------------+ +------------------------------------+ | [App A] [App B] [App C] | | [App A] [App B] [App C] | | [Libs] [Libs] [Libs] | | [Libs] [Libs] [Libs] | | +---------+ +---------+ +-----+ | +------------------------------------+ | |Guest OS | |Guest OS | |Guest| | | DOCKER ENGINE | | | (Linux) | | (Win) | | OS | | +------------------------------------+ | +---------+ +---------+ +-----+ | | HOST OPERATING SYSTEM | | | HYPERVISOR (ESXi / Hyper-V) | | | (Shared Linux Kernel) | | +-------------------------------+ | +------------------------------------+ | | PHYSICAL HARDWARE (CPU/RAM) | | | PHYSICAL HARDWARE (CPU/RAM) | +------------------------------------+ +------------------------------------+
Attribute Virtual Machine (VM) Docker Container
Operating System Full, heavy Guest OS per VM (10 GB - 30 GB each). Shares the Host OS kernel directly (50 MB - 500 MB).
Boot Time Minutes (must boot the entire virtual motherboard & OS). Milliseconds (it is simply an isolated OS process!).
Density 5 to 20 VMs per physical server. Hundreds of containers on the same physical host.

03. The Standard Cargo Shipping Container Analogy

The Historic Breakthrough of 1956:

Before standard shipping containers existed, transporting goods was chaotic. A cargo ship had to load loose bananas, wooden barrels of rum, steel pipes, and cars individually. Loading and unloading took weeks at the docks. In 1956, Malcolm McLean invented the standardized steel shipping container. The cargo vessel and port crane don't care what is packed inside the container—whether it is grand pianos or frozen meat—the dimensions and corner locks are standard. It moves smoothly from container ship to rail car to freight truck.

Docker does the exact same thing for software. Your container can hold a Python FastAPI app, a Java Spring Boot monolith, or a Node.js microservice. The cloud host (Azure ACI, ACA, or AKS) runs it with the exact same standard commands!

04. The 4 Core Docker Pillars

+------------------+ docker build +------------------+ | Dockerfile | ------------------------> | Docker Image | | (Source Recipe) | | (Baked Template)| +------------------+ +------------------+ | docker push | docker run v +------------------+ +------------------+ |Container Registry| <-------------------------- | Docker Container | | (Docker Hub/ACR) | | (Live Instance) | +------------------+ +------------------+
  1. Dockerfile: The plaintext recipe or blueprint that lists instructions line-by-line on how to assemble the software environment.
  2. Docker Image: The compiled, frozen, immutable snapshot containing the code and dependencies. It is read-only.
  3. Docker Container: A live, running instance of an image. If the image is the recipe for a chocolate cake, the container is the physical cake you can eat. You can spin up 10 containers from 1 image!
  4. Container Registry: The online warehouse for storing and sharing Docker images (e.g., Docker Hub, Azure Container Registry - ACR).

05. Dissecting a Real Production Dockerfile

Here is a clean, minimal Dockerfile for a Python Web API:

# 1. Base Image: Start with an official lightweight Python runtime FROM python:3.11-slim # 2. Working Directory: Set the active directory inside the container WORKDIR /app # 3. Copy Dependency Manifest first (enables Docker build caching!) COPY requirements.txt . # 4. Install Dependencies RUN pip install --no-cache-dir -r requirements.txt # 5. Copy Application Source Code COPY . . # 6. Inform Docker that the application listens on port 5000 EXPOSE 5000 # 7. Container Startup Command CMD ["python", "app.py"]

06. Port Forwarding Mechanics: Host Port vs. Container Port

A container runs inside its own isolated network sandbox. By default, your laptop or cloud server cannot talk to it unless you establish a port bridge:

docker run -d -p 8080:5000 my-python-app
User Browser (http://localhost:8080) | v [ HOST MACHINE PORT 8080 ] | (Traffic forwarded via bridge) v [ CONTAINER PORT 5000 ] --> Python app.py receives the HTTP request!

07. Essential Docker CLI Cheatsheet

# 1. Build an image from Dockerfile in current directory docker build -t myapp:v1 . # 2. Run container in detached mode (-d) with port mapping (-p) docker run -d -p 8080:80 --name web-service nginx:alpine # 3. List all currently RUNNING containers docker ps # 4. List ALL containers (including stopped ones) docker ps -a # 5. View live logs streamed from a running container docker logs -f web-service # 6. Open an interactive bash/sh shell inside a live container docker exec -it web-service sh # 7. Stop and remove a container docker stop web-service docker rm web-service # 8. Tag and push to Azure Container Registry (ACR) az acr login --name myregistry docker tag myapp:v1 myregistry.azurecr.io/myapp:v1 docker push myregistry.azurecr.io/myapp:v1
