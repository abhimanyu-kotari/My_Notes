Object-Oriented Programming (Part 1): Classes & Objects

What is this topic? Object-Oriented Programming (OOP) is a way of organizing code by modeling real-world entities using Classes (blueprints) and Objects (instances) that bundle together data (attributes) and actions (methods).
Why do we use it? As programs grow, writing loose functions and scattered variables becomes messy and confusing. We use OOP to build structured, reusable, and secure real-world systems—like bank accounts, user profiles, shopping carts, or game characters—where each object manages its own data and behavior.

01. Evolution: Procedural to Functional to OOP

1. How Did Programming Evolve?

To understand why Object-Oriented Programming exists, look at how developers wrote code through history:

1. Procedural Programming (Step-by-Step Execution)

In the beginning, code was written as one long, top-to-bottom sequence of instructions (e.g. a = 10; b = 20; sum = a + b; diff = a - b). While fine for 10-line scripts, it quickly became an unmaintainable tangle of repeated code as projects grew.

2. Functional / Modular Programming (Reusable Functions)

Next came Functions. Instead of repeating identical code 50 times, we grouped logic inside def calculate_sum(a, b):. This decreased code repetition (redundancy) and made code reusable.

3. Object-Oriented Programming (OOP) — Real-World Modeling

The modern standard for large applications! Instead of managing scattered variables and loose functions, OOP lets us map our code directly to real-world entities (like a Student, a Bank Account, or a Car). An object bundles its own data and its own actions together.

Fun Fact: You Have Already Been Using Objects!

In Python, almost everything is already an object behind the scenes:

  • A string like name = "Rahul" is actually an object of class str! That's why you can call string methods like name.upper() or name.find().
  • A list like marks = [95, 80] is an object of class list, giving you methods like marks.append() and marks.sort().

02. Classes & Objects: Blueprint vs. Instance

1. The Blueprint & Factory Analogy

Before a factory produces a single physical car, engineers must design an architectural blueprint specifying what parts the car has (color, engine size, wheels) and what actions it can perform (drive, stop, accelerate).

Concept What is it? Real-Life Analogy In Python Code
Class A design template or blueprint used to create objects. The architectural drawing of a house or car. class Student:
Object (Instance) The actual, real entity constructed using that blueprint. The physical house built on the plot, or the physical car on the road. s1 = Student()

2. Defining a Class and Creating an Object in Python

To define a class in Python, use the class keyword followed by the class name (by convention, class names start with a Capital letter, such as Student or Car):

python 
# Step 1: Define the Blueprint (Class)
class Student:
    name = "Karan"

# Step 2: Create an actual Object (Instance) from the Blueprint
s1 = Student()
print(s1.name)  # Output: Karan

# Step 3: We can create another Student object!
s2 = Student()
print(s2.name)  # Output: Karan

In the example above, both students share the same hard-coded name. But in real life, every student has their own unique name and marks! How do we give each object its own unique data? That's where the Constructor comes in!

03. The __init__() Constructor

1. What is a Constructor?

A Constructor is a special function inside a class that automatically executes the instant a new object is created.

In Python, this constructor function is always named __init__() (short for initialization, with two underscores before and after):

python 
class Student:
    # The Constructor method
    def __init__(self):
        print("Adding new student into database...")

# Notice: We never explicitly called s1.__init__()!
# The moment Student() is instantiated, __init__ runs automatically!
s1 = Student()  # Prints: Adding new student into database...
s2 = Student()  # Prints: Adding new student into database...

2. Passing Custom Data into the Constructor

We can pass arguments directly into the class parentheses when creating the object, just like calling a function:

python 
class Student:
    def __init__(self, name, marks):
        self.name = name
        self.marks = marks
        print(f"Registered: {self.name} with {self.marks} marks")

# Creating two distinct students with their own custom information
s1 = Student("Karan", 97)   # Prints: Registered: Karan with 97 marks
s2 = Student("Arjun", 88)   # Prints: Registered: Arjun with 88 marks

print(s1.name, s1.marks)  # Karan 97
print(s2.name, s2.marks)  # Arjun 88

04. The 'self' Parameter Explained (Who am I?)

1. What Exactly is 'self'?

Beginners often get confused by self. But the concept is very simple:

Simple Definition: 'self' means "This Current Object"

When you create 100 students from the Student class, how does Python know whose name or marks you are talking about?

self is a pointer/reference to the specific object that is currently being created or operated on.

  • When creating s1, self points to s1. So self.name = "Karan" creates s1.name = "Karan".
  • When creating s2, self points to s2. So self.name = "Arjun" creates s2.name = "Arjun".
python 
class Student:
    def __init__(self, name):
        print("Memory address of self:", self)
        self.name = name

s1 = Student("Karan")
print("Memory address of s1:  ", s1)
# Both print the exact same memory location: <__main__.Student object at 0x00000...>!

Rule: The first parameter of __init__() (and any normal method inside a class) must always be self. Python automatically passes the object into self behind the scenes whenever you call it.

05. Class Attributes vs. Instance Attributes

Any variable stored inside a class is called an Attribute. But attributes come in two distinct flavors:

Attribute Type Where is it defined? Memory Allocation Real-Life Example
Instance Attribute (Object level) Inside __init__ using self.var_name Saved separately for each individual object. Student's name, roll_no, marks (unique to each student).
Class Attribute (Class level) Directly inside the class body, outside any function. Saved only once in memory and shared across all objects! college_name = "ABC College" (common for all 1,000 students).

Why do we need Class Attributes? (Saving Memory)

If a college has 5,000 students, storing college_name = "ABC College" inside every student's individual memory wastes 5,000 slots of RAM for the exact same text!
By creating a Class Attribute, Python allocates it once in memory, and all 5,000 student objects share that single piece of data.

python 
class Student:
    # Class Attribute (Shared by ALL students)
    college_name = "ABC College"

    def __init__(self, name, marks):
        # Instance Attributes (Unique to EACH student)
        self.name = name
        self.marks = marks

s1 = Student("Karan", 95)
s2 = Student("Arjun", 88)

# Accessing Class Attribute: can be accessed via object OR class name
print(s1.college_name)       # ABC College
print(Student.college_name)  # ABC College (Recommended Pythonic syntax)

The Precedence Rule (What if names clash?)

Priority Rule: Instance Attribute > Class Attribute

If a class attribute and an instance attribute share the exact same variable name, Python always gives higher priority to the Instance (Object) attribute!

python
class Student:
    name = "Anonymous"  # Class attribute

    def __init__(self, name):
        self.name = name  # Instance attribute

s1 = Student("Karan")
print(s1.name)  # Prints "Karan", NOT "Anonymous"!

06. Methods: Giving Actions to Objects

1. What is a Method?

A class represents two things:

  • Attributes (Data): What the object has (e.g. name, marks, balance).
  • Methods (Actions): What the object can do (e.g. calculate average, deposit money, drive).

A Method is simply a function defined inside a class that belongs to the object.

python 
class Student:
    def __init__(self, name, marks):
        self.name = name
        self.marks = marks

    # Method 1: Greets the student using their specific name
    def welcome(self):
        print(f"Welcome to college, {self.name}!")

    # Method 2: Returns the student's marks
    def get_marks(self):
        return self.marks

s1 = Student("Karan", 97)
s1.welcome()              # Output: Welcome to college, Karan!
print(s1.get_marks())     # Output: 97

2. Modifying Attributes

Attributes are not locked permanently. You can change them directly at any point:

python
s1.name = "Iron Man"
s1.welcome()  # Output: Welcome to college, Iron Man!

07. Static Methods & The @staticmethod Decorator

1. Why do we need Static Methods?

Normal methods always require self as the first argument because they read or modify an object's specific data (like self.name).

What if you want a utility function inside your class that doesn't need to read any student's name or marks (for example, a simple helper that prints a general greeting or does a math formula)?

If you define a normal method without self, Python throws an error:
TypeError: welcome() takes 0 positional arguments but 1 was given.

2. The @staticmethod Solution

To tell Python "This method belongs to the class, not to any individual object instance, so do NOT pass self", we place the @staticmethod decorator above the function:

python 
class Student:
    def __init__(self, name):
        self.name = name

    # Regular Method (uses self to access student name)
    def say_name(self):
        print("My name is:", self.name)

    # Static Method (does not need self or any instance data!)
    @staticmethod
    def college_motto():
        print("Motto: Learn, Build, and Innovate!")

s1 = Student("Karan")
s1.say_name()          # My name is: Karan
s1.college_motto()     # Motto: Learn, Build, and Innovate!
Student.college_motto() # Can also be called directly on the class!
What is a Decorator?

In Python, anything starting with an @ symbol above a function is called a Decorator. A decorator wraps around a function to adjust or enhance its behavior without permanently altering the function's internal code.

08. Core Pillars: Abstraction & Encapsulation

In computer science and software interviews, you will frequently hear about the 4 Pillars of OOP:

  1. Abstraction (Covered today)
  2. Encapsulation (Covered today)
  3. Inheritance (Covered in Part 2)
  4. Polymorphism (Covered in Part 2)

1. Abstraction (Hiding Complexity, Showing Essentials)

Real-Life Analogy: Driving a Car

When you sit in a car and turn the key or press the accelerator, you only see a simple dashboard and a foot pedal. You do not need to see fuel injecting into the engine, pistons firing, spark plugs sparking, or transmission gears shifting!

The car manufacturer abstracts away (hides) all the complicated mechanical machinery and exposes only the essential controls you need to drive.

python 
class Car:
    def __init__(self):
        self.clutch = False
        self.acc = False
        self.brake = False

    def start(self):
        # Complex internal mechanics are handled inside the class:
        self.clutch = True
        self.acc = True
        print("Car started safely.")

# The user only interacts with the clean, simple interface:
my_car = Car()
my_car.start()  # Prints: Car started safely.

2. Encapsulation (The Protective Capsule)

Real-Life Analogy: A Medical Capsule

Think of a medicinal capsule. Inside the single shell, multiple ingredients are wrapped together into one clean pill.

In programming, Encapsulation means wrapping data (attributes) and related functions (methods) together into a single unit (the class/object).

Every class we have written today—like Student holding both name and get_marks()—is a live demonstration of encapsulation!

09. Practice 1: Student Class & Average Marks

Problem Statement:

Create a Student class that takes the student's name and a list of marks for 3 subjects in its constructor. Then create a method get_average() that computes and prints their average score.

python 
class Student:
    def __init__(self, name, marks):
        self.name = name
        self.marks = marks  # Expecting a list of numbers

    def get_average(self):
        # Calculate the sum of all marks in the list
        total_sum = 0
        for val in self.marks:
            total_sum += val
        
        # Divide by total subjects to find average
        avg = total_sum / len(self.marks)
        print(f"Hi {self.name}, your average score is: {avg:.2f}")

# Create student Tony Stark with 3 subject scores
s1 = Student("Tony Stark", [99, 98, 97])
s1.get_average()  # Output: Hi Tony Stark, your average score is: 98.00

# Changing attribute dynamically:
s1.name = "Iron Man"
s1.get_average()  # Output: Hi Iron Man, your average score is: 98.00

10. Practice 2: Real-World Banking System

Problem Statement:

Create an Account class with two attributes: balance and account_no.
Implement methods to:

  • debit(amount): Subtracts money from balance and displays updated total.
  • credit(amount): Adds money into balance and displays updated total.
  • get_balance(): Returns current balance.
python 
class Account:
    def __init__(self, balance, account_no):
        self.balance = balance
        self.account_no = account_no

    # Debit (Withdraw) Method
    def debit(self, amount):
        if amount > self.balance:
            print(f"Declined: Insufficient funds to withdraw Rs {amount}")
            return
        self.balance -= amount
        print(f"Rs {amount} was debited.")
        print(f"Total remaining balance = Rs {self.get_balance()}")

    # Credit (Deposit) Method
    def credit(self, amount):
        self.balance += amount
        print(f"Rs {amount} was credited.")
        print(f"Total remaining balance = Rs {self.get_balance()}")

    # Helper method to get current balance
    def get_balance(self):
        return self.balance

# --- Simulating Customer Transactions ---
acc1 = Account(10000, 12345)
print(f"Account #{acc1.account_no} initialized with Rs {acc1.get_balance()}")

acc1.debit(1000)    # Debits 1,000 -> Balance: Rs 9,000
acc1.credit(500)    # Credits 500  -> Balance: Rs 9,500
acc1.credit(40000)  # Salary credited -> Balance: Rs 49,500
acc1.debit(10000)   # Rent debited    -> Balance: Rs 39,500
