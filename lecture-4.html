Dictionary & Sets

What is this topic? A Dictionary stores related information in key : value pairs (just like looking up a word to find its definition), while a Set is an unordered collection that automatically removes all duplicate values.
Why do we use it? We use dictionaries to represent real-world entities—such as a student profile ("name": "Rahul", "marks": 95) or a product catalog—so you can find details instantly by name. We use sets whenever we need unique items, like filtering out duplicate phone numbers or finding common friends.

01. What is a Dictionary & Syntax

1. Real-World Analogy & Architectural Need

In human linguistics, a physical dictionary is structured around word-to-meaning pairs. Each unique word represents an identifier, and beside it sits its associated definition. When looking up information, a person does not search through arbitrary page numbers or sequential indices; they query the dictionary directly by the word.

In computer science, this associative model is called an Associative Array, Map, or Hash Map. In Python, this core concept is implemented via the built-in dict data type.

Definition: Python Dictionary

A dictionary is a built-in, mutable, associative data structure used to store collections of data in key:value pairs. It belongs to the class dict.

  • Key: The unique lookup identifier (acts like the word in a dictionary).
  • Value: The data associated with that specific key (acts like the definition in a dictionary).

2. Dictionary Syntax

Dictionaries are declared using curly braces { }. Each entry consists of a key and a value separated by a colon :, with multiple pairs delimited by commas:

dictionary_name = { "key1": value1, "key2": value2 }
python 
# Declaring a dictionary holding a profile record
info = {
    "name": "Apna College",
    "age": 25,
    "is_adult": True,
    "marks": 94.4,
    "subjects": ["Python", "C", "Java"],
    "topics": ("dict", "set")
}

print("Dictionary contents:", info)
print("Data type:", type(info))    # <class 'dict'>
print("Number of pairs:", len(info)) # 6
Terminal Output:
Dictionary contents: {'name': 'Apna College', 'age': 25, 'is_adult': True, 'marks': 94.4, 'subjects': ['Python', 'C', 'Java'], 'topics': ('dict', 'set')}
Data type: <class 'dict'>
Number of pairs: 6

3. Allowed Types for Keys and Values

Component Permitted Python Types Restrictions & Rules
Values Any data type: int, float, str, bool, list, tuple, dict, set Zero restrictions. Values can be duplicates, mutable, or complex nested structures.
Keys Immutable types only: str, int, float, bool, tuple Must be hashable. Mutable containers like list or dict cannot be keys. In production, strings are the gold standard for keys.

02. Core Properties & Mutability

1. The Three Fundamental Architectural Rules of Dictionaries

  1. Unindexed & Key-Addressed: Unlike lists or strings where elements are addressed by numerical coordinates (0, 1, 2...), dictionary elements are looked up strictly by their key: dict[key].
  2. Mutable: You can add new key-value pairs, update existing values, or delete entries dynamically after creation.
  3. Unique Keys (No Duplicate Keys Allowed): A dictionary cannot contain duplicate keys. If you assign to an already existing key, Python overwrites the old value with the new one.
⚠️
The Bracket Notation KeyError Trap

When retrieving a value using square bracket notation dict[key], if the specified key does not exist in the dictionary, Python raises a fatal KeyError and crashes the program.

python 
student = {
    "name": "Karan",
    "score": 92.5,
    "age": 20
}

# 1. Accessing values via key
print("Student Name:", student["name"])   # Karan
print("Student Score:", student["score"]) # 92.5

# 2. Mutating an existing key (Overwrites previous value)
student["score"] = 97.0
print("Updated Score:", student["score"]) # 97.0

# 3. Adding a brand-new key-value pair
student["city"] = "Delhi"
print("After adding city:", student)

# 4. Attempting to access a nonexistent key
# print(student["address"])  --> Raises KeyError: 'address'
Terminal Output:
Student Name: Karan
Student Score: 92.5
Updated Score: 97.0
After adding city: {'name': 'Karan', 'score': 97.0, 'age': 20, 'city': 'Delhi'}

2. Initializing an Empty (Null) Dictionary

In production programming, algorithms frequently instantiate an empty dictionary and populate it incrementally based on user inputs or network requests:

python 
# Empty dictionary initialization
null_dict = {}
print("Empty dictionary:", null_dict)
print("Type:", type(null_dict))  # <class 'dict'>

# Populating dynamically
null_dict["title"] = "Python Masterclass"
print("Populated:", null_dict)
Terminal Output:
Empty dictionary: {}
Type: <class 'dict'>
Populated: {'title': 'Python Masterclass'}

03. Nested Dictionaries

1. What is Nesting in Dictionaries?

Similar to nesting conditional statements within one another, dictionary nesting refers to storing a dictionary as the value of another dictionary's key.

This pattern mirrors real-world hierarchical data formats like JSON (JavaScript Object Notation), which forms the backbone of web APIs and modern database documents.

python 
# Nested Dictionary representing a student academic record
student = {
    "name": "Rahul Kumar",
    "subjects": {
        "physics": 97,
        "chemistry": 98,
        "math": 95
    }
}

print("Full student record:", student)
print("Subjects dictionary:", student["subjects"])

# Accessing a nested value using chained bracket lookups:
print("Chemistry Marks:", student["subjects"]["chemistry"]) # 98
Terminal Output:
Full student record: {'name': 'Rahul Kumar', 'subjects': {'physics': 97, 'chemistry': 98, 'math': 95}}
Subjects dictionary: {'physics': 97, 'chemistry': 98, 'math': 95}
Chemistry Marks: 98

04. Built-in Dictionary Methods

1. Deep Dive into the 5 Core Dictionary Methods

Method Description Return Type
dict.keys() Returns a view object of all outer keys in the dictionary. dict_keys (convertible to list)
dict.values() Returns a view object of all values in the dictionary. dict_values (convertible to list)
dict.items() Returns all (key, value) pairs as a collection of tuples. dict_items (convertible to list of tuples)
dict.get(key) Returns the value of key safely. Returns None if key does not exist. Value or None (no crash)
dict.update(new_dict) Merges new key-value pairs into the dictionary in place. Overwrites duplicates. None

2. Architectural Comparison: dict[key] vs. dict.get(key)

Understanding why Python provides both bracket notation and the .get() method is a hallmark of professional software engineering:

💡
Production Stability: Why .get() is Safer

When you write student["name2"] and the key is missing, Python raises an uncaught KeyError, which terminates the entire application and prevents all subsequent lines of code from executing.

In contrast, student.get("name2") gracefully returns None. This prevents application crashes and allows developers to handle missing data cleanly using fallback logic.

python 
student = {
    "name": "Rahul Kumar",
    "subjects": {"phy": 97, "chem": 98, "math": 95}
}

# 1. dict.keys()
all_keys = student.keys()
print("dict_keys view:", all_keys)
print("Typecast to list:", list(all_keys)) # ['name', 'subjects']

# 2. dict.values()
print("dict_values:", list(student.values()))

# 3. dict.items(): Key-Value pairs as Tuples
print("dict_items:", list(student.items()))
# Output: [('name', 'Rahul Kumar'), ('subjects', {'phy': 97, 'chem': 98, 'math': 95})]

# 4. dict.get(key) vs dict[key]
print("Safe get on valid key:", student.get("name"))      # Rahul Kumar
print("Safe get on missing key:", student.get("address"))  # None (No error!)

# 5. dict.update(new_dict)
student.update({"city": "Delhi", "age": 16})
print("After update:", student)
Terminal Output:
dict_keys view: dict_keys(['name', 'subjects'])
Typecast to list: ['name', 'subjects']
dict_values: ['Rahul Kumar', {'phy': 97, 'chem': 98, 'math': 95}]
dict_items: [('name', 'Rahul Kumar'), ('subjects', {'phy': 97, 'chem': 98, 'math': 95})]
Safe get on valid key: Rahul Kumar
Safe get on missing key: None
After update: {'name': 'Rahul Kumar', 'subjects': {'phy': 97, 'chem': 98, 'math': 95}, 'city': 'Delhi', 'age': 16}

05. Introduction to Sets in Python

1. Mathematical Foundation

In mathematics, a set is defined as a well-defined collection of distinct, unique objects. Python mirrors this mathematical construct directly through its built-in primitive collection set.

A set is an unordered, unindexed collection of unique elements.

Syntax: Curly Braces Without Key-Value Pairs

Like dictionaries, sets use curly braces { }, but contain individual comma-separated values rather than key:value associations:

collection = {1, 2, 3, 4, 5}
python 
collection = {1, 2, 3, 4}

print("Set contents:", collection)
print("Data type:", type(collection))  # <class 'set'>
print("Length:", len(collection))        # 4
Terminal Output:
Set contents: {1, 2, 3, 4}
Data type: <class 'set'>
Length: 4

06. Set Properties & The Empty Set Trap

1. Automatic Deduplication of Elements

The most famous property of a Python set is that duplicate values are strictly forbidden. When duplicate items are provided in a set declaration or added later, Python silently ignores the duplicates and retains only a single instance of each value:

python 
# Set with intentional duplicate values
nums = {1, 2, 2, 2, 3, "hello", "world", "world"}

print("Deduplicated Set:", nums)
print("Total unique count:", len(nums)) # 4
Terminal Output:
Deduplicated Set: {1, 2, 3, 'hello', 'world'}
Total unique count: 5

2. Unordered & Unindexed

Sets have no sequential index. You cannot write nums[0] or slice a set with nums[1:3]. Doing so raises TypeError: 'set' object is not subscriptable. The print order of elements can vary across runs.

3. The Empty Set Syntax Trap

Because dictionaries historically came first in Python, empty curly braces {} are reserved for creating an empty dictionary, NOT an empty set!

⚠️
The Empty Set Syntax Trap

s = {} creates an empty dict (class dictionary).

To create an empty set, you MUST invoke the built-in constructor function: s = set().

python 
# WRONG: Creates an empty dict, not a set
wrong_empty = {}
print(type(wrong_empty))  # <class 'dict'>

# CORRECT: Creates an empty set
real_empty_set = set()
print(type(real_empty_set))  # <class 'set'>
Terminal Output:
<class 'dict'>
<class 'set'>

07. Mutability vs. Hashability

1. Set Container Mutability vs. Element Immutability

A common interview and conceptual question is: "Are sets mutable or immutable in Python?"

The Dual Nature of Sets
  • The Set Container itself is MUTABLE: You can dynamically add new elements with .add() and remove items with .remove().
  • The Elements INSIDE a Set must be strictly IMMUTABLE (Hashable): Every item stored inside a set must be an immutable type (int, float, str, bool, tuple). Mutable types like list, dict, or other set objects cannot be stored inside a set.

2. What is Hashability?

Sets in Python are implemented under the hood as Hash Tables. When an element is added to a set, Python passes the element through a mathematical hash function (hash(x)) that generates a fixed integer hash value.

This hash value dictates the exact memory address (bucket) where the item is stored, allowing Python to achieve lightning-fast $O(1)$ constant-time lookup and deduplication.

⚠️
The Unhashable Type Error

If an object is mutable (like a list), its contents can change at any moment. If its contents changed, its hash value would change, corrupting the hash table's lookup integrity.

Therefore, Python strictly prohibits mutable types inside sets:
s.add([1, 2, 3]) # Raises TypeError: unhashable type: 'list'

python 
s = set()

# Valid: Adding immutable types
s.add(1)
s.add("hello")
s.add((10, 20))  # Tuples are immutable and hashable!
print("Valid set:", s)

# Invalid: Attempting to store a list
# s.add([1, 2])  --> TypeError: unhashable type: 'list'
Terminal Output:
Valid set: {1, 'hello', (10, 20)}

08. Built-in Set Methods (Union & Intersection)

1. Modification Methods: add, remove, clear, pop

Method Operation & Behavior Return Value
set.add(el) Adds immutable element el to the set. Duplicates silently ignored. None
set.remove(el) Removes el from the set. Raises KeyError if element is absent. None
set.clear() Empties all elements from the set, resetting it to set(). None
set.pop() Removes and returns an arbitrary (random) element from the set. Popped element
python 
tech = set()

# 1. set.add()
tech.add("Python")
tech.add("Java")
tech.add("C++")
print("After add:", tech)

# 2. set.remove()
tech.remove("Java")
print("After remove('Java'):", tech)

# 3. set.pop(): Removes an arbitrary element
popped = tech.pop()
print("Popped element:", popped)
print("Remaining in set:", tech)

# 4. set.clear()
tech.clear()
print("After clear:", tech)  # set()
Terminal Output:
After add: {'Python', 'C++', 'Java'}
After remove('Java'): {'Python', 'C++'}
Popped element: Python
Remaining in set: {'C++'}
After clear: set()

2. Set Operations: Union & Intersection

Python sets natively implement mathematical set operations:

  • Union (set1.union(set2)): Merges all unique elements from both sets into a new set ($A \cup B$). Any common elements are retained exactly once. Neither original set is mutated.
  • Intersection (set1.intersection(set2)): Returns a new set containing exclusively the elements present in both sets ($A \cap B$).
python 
set1 = {1, 2, 3}
set2 = {2, 3, 4}

# Union: Combines all unique elements (1, 2, 3, 4)
u_res = set1.union(set2)
print("set1 union set2:", u_res)

# Intersection: Returns common elements only (2, 3)
i_res = set1.intersection(set2)
print("set1 intersection set2:", i_res)

# Original sets remain completely untouched
print("Original set1 intact:", set1)
print("Original set2 intact:", set2)
Terminal Output:
set1 union set2: {1, 2, 3, 4}
set1 intersection set2: {2, 3}
Original set1 intact: {1, 2, 3}
Original set2 intact: {2, 3, 4}

Task 04 Sets Puzzle Hash Equality Tuples
Figure out a way to store 9 (integer) and 9.0 (float) as separate, distinct values in a Python set.
The Technical Dilemma:

In Python, 9 == 9.0 evaluates to True, and their hash values are identical (hash(9) == hash(9.0)). Because sets enforce equality and hash uniqueness, declaring {9, 9.0} automatically deduplicates into a single value {9}.

Two Production Solutions:
  1. String Representation: Store one or both values as textual strings: {9, "9.0"} or {"9", 9.0}.
  2. Type-Value Tuples (Best Practice): Wrap each value in an immutable tuple paired with its explicit type tag: {("int", 9), ("float", 9.0)}.
View Python Solution & Explanation
python 
# Demonstration of the 9 vs 9.0 issue:
vanilla_set = {9, 9.0}
print("Vanilla deduplication:", vanilla_set) # {9}

# Solution Method 1: Using String Conversion
sol1 = {9, "9.0"}
print("Solution 1 (String):", sol1)           # {9, '9.0'}

# Solution Method 2: Using Type-Value Tuples (Recommended)
sol2 = {
    ("int", 9),
    ("float", 9.0)
}
print("Solution 2 (Tuples):", sol2)           # {('float', 9.0), ('int', 9)}
Terminal Output:
Vanilla deduplication: {9}
Solution 1 (String): {9, '9.0'}
Solution 2 (Tuples): {('float', 9.0), ('int', 9)}
