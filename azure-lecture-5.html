Module 05 Azure ACA Serverless Microservices KEDA Autoscaling Envoy Ingress Zero to N Replicas

Azure Container Apps (ACA)

What is this module about? The modern sweet spot for containerized microservices and web APIs: running containers serverlessly on top of Kubernetes, Envoy proxy, KEDA, and Dapr without managing clusters, master nodes, or complex YAML manifests. Understanding Environments, Revisions, Canary traffic splitting, and scaling to zero instances to eliminate idle bills.
Why is this critical for engineers? Modern cloud applications require HTTP ingress, autoscaling on traffic spikes, and versioning. ACA gives you enterprise Kubernetes power with the operational simplicity of serverless.

01. What is Azure Container Apps (ACA)?

In modern software engineering, web applications are composed of multiple independent microservices: an authentication service, an order processing API, a frontend web portal, and asynchronous message queue workers.

While ACI is ideal for executing a single isolated container task, it lacks built-in HTTP ingress routing, autoscaling based on incoming request spikes, and versioning. Conversely, Azure Kubernetes Service (AKS) gives you ultimate power, but requires you to manage master control planes, node pools, networking overlays, Helm charts, and complex manifests.

Azure Container Apps (ACA) is the "Goldilocks" solution. It is a serverless container platform built on Kubernetes (AKS), Envoy proxy, KEDA (Kubernetes Event-driven Autoscaling), and Dapr (Distributed Application Runtime)—without exposing any Kubernetes cluster management complexity!

02. The Food Truck Festival Analogy

The Microservice Festival:

- Virtual Machine (VM): You buy a permanent restaurant building. You pay mortgage, electricity, and maintenance 24/7 even if no customers show up.

- ACI (Container Instance): You rent a single hot dog cart for an afternoon. When the job ends, you pack up. Very fast, but it cannot expand to a full festival.

- ACA (Container Apps): A modern, managed Food Truck Festival. The festival venue provides the fenced security perimeter, clean water, and public gate (Container Apps Environment). You park your specialized food trucks (Burger Truck, Taco Truck, Ice Cream Truck). If a huge hungry crowd rushes the Taco Truck at 8:00 PM, the festival instantly allows two more Taco Trucks to pull up and serve the queue. When the crowd disperses at midnight, all trucks leave and your rent drops to $0!

03. Core Building Blocks & Ingress

+--------------------------------------------------------------------------+ | CONTAINER APPS ENVIRONMENT (VNet Boundary) | | | | [ Public HTTPS Traffic from Internet ] | | | | | +----------------------+ | | | Built-in Envoy Ingress| (SSL Termination & Routing) | | +----------+-----------+ | | | | | +----------------+----------------+ | | | (80% Traffic) | (20% Traffic) | | v v | | +--------------------+ +--------------------+ | | | Revision 1 (v1.0) | | Revision 2 (v2.0) | | | | [Pod 1] [Pod 2] | | [Pod 1] | | | +--------------------+ +--------------------+ | | Frontend Microservice Canary Test Microservice | | | | | (Internal Service-to-Service Calls) | | v | | +--------------------+ +--------------------+ | | | Backend Order API | | Event Processor | | | | (Internal Ingress) | | (KEDA Scaler) | | | +--------------------+ +--------------------+ | +--------------------------------------------------------------------------+

Key Concepts:

  • Container Apps Environment: The secure network wrapper. All apps inside the same environment share the same Virtual Network (VNet) and send telemetry to the same Log Analytics workspace.
  • External Ingress: Gives your container app a public HTTPS URL with automatic TLS/SSL certificates managed by Microsoft for free.
  • Internal Ingress: Restricts access so only other containers within the same ACA Environment can communicate with the service (perfect for databases and internal microservices).

04. Revisions & Traffic Splitting (Canary Deployments)

Every time you update container configuration or deploy a new Docker image tag, Azure creates an immutable Revision (e.g. app--v1, app--v2).

🚀 Zero-Downtime Canary Rollouts: You can split live web traffic between revisions with zero external load balancers. Route 90% of user traffic to v1.0 and 10% to v2.0. If the new version throws errors, flip 100% of traffic back to v1.0 in one second!

05. KEDA Autoscaling (Scale to Zero)

ACA uses KEDA (Kubernetes Event-driven Autoscaling) under the hood:

  • Scale to 0 Replicas ($0 Compute Cost): If your internal company app receives zero traffic between 10:00 PM and 6:00 AM, ACA shuts down all running container replicas. You pay $0 for compute during idle hours!
  • Scale Out on Demand: When an HTTP request hits the Envoy ingress in the morning, ACA wakes up a container replica in milliseconds and routes the request.
  • Event-Driven Scalers: Scale based on HTTP concurrent requests, CPU/Memory percentages, or queue depths (Azure Service Bus, RabbitMQ, Kafka).

06. Azure CLI Deployment Walkthrough

# 1. Install Container Apps Extension & Register Providers az extension add --name containerapp --upgrade az provider register --namespace Microsoft.App # 2. Create the ACA Environment az containerapp env create \ --name my-aca-env \ --resource-group my-rg \ --location eastus # 3. Deploy a Public Container App az containerapp create \ --name my-web-app \ --resource-group my-rg \ --environment my-aca-env \ --image mcr.microsoft.com/azuredocs/aci-helloworld:latest \ --target-port 80 \ --ingress external \ --query properties.configuration.ingress.fqdn # 4. Configure Traffic Splitting (80% to v1, 20% to v2) az containerapp ingress traffic set \ --name my-web-app \ --resource-group my-rg \ --revision-weight my-web-app--v1=80 my-web-app--v2=20
